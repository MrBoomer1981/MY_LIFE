# Инфраструктура как система слоёв

> [!abstract] Суть
> ИТ-инфраструктуру удобно рассматривать как девять взаимосвязанных слоёв. Разделение помогает локализовать ограничения и распределять ответственность; безопасность, надёжность и мониторинг охватывают весь стек.

## Предмет курса и основные понятия

Вводный курс Артёма Береснева (ИТМО) рассматривает корпоративную инфраструктуру в контексте ИИ, с практикой на Linux. Разработка ПО, управление разработкой и ITSM находятся вне его рамок. Представленный PDF содержит введение, лекцию 2 о Servers и две части лекции 5 о Storage.

Информационная система — организационно упорядоченная совокупность данных, технологий и процессов хранения, обработки, поиска и передачи информации. Это работающая система целиком, например CRM компании, включая людей и организационные процессы.

Технологический стек — набор языков, библиотек, фреймворков и инструментов разработки и запуска ПО: например, Python, Flask, React и Postgres. Он описывает технологический состав продукта.

Корпоративная ИТ-инфраструктура — аппаратные и программные ресурсы, сети и сервисы, поддерживающие информационные процессы организации: серверы, СХД, сеть, виртуализация и ОС. Одна инфраструктура может обслуживать несколько информационных систем.

## Девять слоёв

Модель курса связана с облачной эталонной архитектурой NIST. Слои — условный способ описания, реальные зависимости не всегда образуют строго линейную лестницу. Каждый слой скрывает детали механизмов и предоставляет сервисы другим компонентам.

| Слой | Назначение | Примеры из источника |
|---|---|---|
| Application | Пользовательская функциональность настольных, веб-, мобильных и серверных приложений | Яндекс.Маркет, Trello, MS Office, AI-агенты |
| Data | Хранение, управление и обработка структурированных и неструктурированных данных: файлов, таблиц, объектов БД, blob | Qdrant, Chroma, Postgres, MS SQL, MongoDB, Google BigQuery |
| Runtime | Среда исполнения и доступные программе контексты | Node.js, JRE, PHP, .NET, CUDA Runtime API |
| Middleware | Связь компонентов и доступ к ресурсам через программные интерфейсы | RPC, ODBC, JDBC, Kafka, RabbitMQ, Azure Service Bus; компоненты CUDA и СУБД могут выполнять соответствующие функции |
| OS | Управление оборудованием и сервисы программам через API | Ubuntu, Windows Server, RHEL, Android |
| Virtualization | Абстракция ресурсов и изоляция сред | VMware vSphere, Hyper-V, KVM, VirtualBox, Parallels; Docker — контейнеризация, Kubernetes — управление контейнерами |
| Servers | Физические вычислительные ресурсы | CPU, GPU, RAM |
| Storage | Хранение данных и доступ к ним | DAS, NAS, SAN, SDS, Amazon S3, Google Cloud Storage, NetApp |
| Networking | Соединение узлов, маршрутизация и защита передачи | Коммутаторы, маршрутизаторы, протоколы, SDN — Software Defined Networking |

## Runtime и Middleware

Runtime исполняет код: без Node.js файл `server.js` остаётся текстом. Middleware обеспечивает взаимодействие с другими компонентами: JDBC/ODBC связывают программу с БД, брокеры сообщений — с другими сервисами. MOM (Message-Oriented Middleware) — промежуточное ПО обмена сообщениями. ELK — Elasticsearch, Logstash и Kibana, стек сбора, поиска и визуализации логов.

Пример минимального сервера из источника:

```javascript
const http = require('http');
const hostname = '127.0.0.1';
const port = 3000;
const server = http.createServer((req, res) => {
  res.statusCode = 200;
  res.setHeader('Content-Type', 'text/plain');
  res.end('Hello World\n');
});
server.listen(port, hostname, () => {
  console.log(`Server running at http://${hostname}:${port}/`);
});
```

Код относится к Application, Node.js — к Runtime, сетевые механизмы, которыми пользуется `listen()`, предоставляет ОС. Сервер слушает локальный адрес и одинаково отвечает на любой запрос.

## Зачем инфраструктура специалисту по ИИ

В источнике приведены три истории. В первой неверная конфигурация ELK привела к утечке данных примерно 150 млн пользователей в 2020 году. Это иллюстрация нарушения конфиденциальности на уровне инфраструктуры и данных; подробности события в PDF не подтверждены отдельным источником.

Во второй для обучения на примерно 12 ТБ фотографий использовали NVIDIA A100, Xeon и 256 ГБ ОЗУ, но единственный HDD на 15 ТБ не успевал подавать данные. GPU простаивал. Решением стало ярусное хранение с быстрым NVMe SSD и ёмким HDD. В рассказе отмечены сорванные сроки и почти 100 тысяч потерь; валюта не уточняется. Смысл примера — ограничение на Storage может проявляться как медленная работа Application.

В третьей AI-стартап по защите блокчейнов сталкивался с разнородными технологиями клиентов. ML-инженеру требовались навыки software engineer и понимание архитектуры. Лектор связывает ценность фундаментального образования с кругозором и умением разбираться в незнакомом; тезисы о смене профессий ролями и автоматизации являются его прогнозом.

Процессор, память, диски и сеть образуют цепочку ресурсов. Ускорение компонента помогает, если именно он ограничивает нагрузку. Задержка — время отдельной операции, пропускная способность — объём работы за единицу времени.

## Облачные модели и ответственность

Таблица описывает типичное разделение; конкретная услуга определяет точную границу.

| Модель | Провайдер обслуживает | Пользователь обслуживает | Пример |
|---|---|---|---|
| On-premise | Внешнего облачного провайдера может не быть | Весь стек | Собственный серверный зал |
| IaaS — Infrastructure as a Service | Сеть, хранение, серверы, виртуализацию | ОС и расположенное выше ПО и данные | Облачная VM |
| PaaS — Platform as a Service | Инфраструктуру и платформу исполнения | Приложение и данные | Платформа загрузки кода |
| SaaS — Software as a Service | Стек вплоть до приложения | Свои данные, настройки и доступы в рамках сервиса | Trello, Office 365 |

## Сквозные процессы

Безопасность обеспечивает требуемую конфиденциальность, целостность и доступность — CIA (Confidentiality, Integrity, Availability). Надёжность означает сохранение требуемой функциональности и доступности; её поддерживают RAID на Storage, резервные блоки питания на Servers, репликация на Data. Мониторинг — непрерывное наблюдение, оценка и анализ серверов, сетей, БД и приложений ради надёжности, эффективности и безопасности.

Эти процессы охватывают все слои. Сами слои необязательны: bare metal работает без виртуализации, простой скрипт может обходиться без Middleware.

## Виртуализация и контейнеры

Виртуальная машина предоставляет среду виртуального оборудования с собственной гостевой ОС. Контейнер изолирует процессы в рамках ядра ОС, на котором запущен контейнерный runtime. Поэтому контейнер — не отдельная полноценная виртуальная машина.

Образ описывает файловую основу и окружение запуска; контейнер — конкретный экземпляр выполнения с собственным состоянием. Одинаковый образ облегчает воспроизводимость, но не отменяет различий архитектуры процессора, внешних данных и конфигурации.

На системе, где Linux-контейнеры работают внутри Linux-виртуальной машины, они делят ядро этой машины. Утверждение о разделяемом ядре относится именно к среде запуска контейнеров.
