# Python — словари, множества и отсутствующие значения

> [!abstract] Суть
> Множество отвечает на вопросы о принадлежности и сочетании наборов, словарь связывает ключ со значением. Наличие записи, истинность её значения и поведение при отсутствии нужно различать.

## Операции над множествами

Элементы `set` уникальны по правилам хеша и равенства: [[Python — хешируемость и равенство ключей]]. В лекции множества представляют библиотеки игр и список желаемого:

```python
mine = {220, 400, 440, 620, 730}
friend = {400, 440, 550, 570, 620}
wishlist = {546560, 550, 400}

print(sorted(mine & friend))   # [400, 440, 620]
print(sorted(mine | friend))   # [220, 400, 440, 550, 570, 620, 730]
print(sorted(wishlist - mine)) # [550, 546560]
print(sorted(mine ^ friend))   # [220, 550, 570, 730]
```

| Операция | Смысл |
|---|---|
| `A & B` | Пересечение: элементы обоих наборов |
| `A | B` | Объединение: элементы хотя бы одного набора |
| `A - B` | Разность: элементы первого, которых нет во втором |
| `A ^ B` | Симметрическая разность: элементы ровно одного из наборов |

Разность зависит от порядка операндов. `sorted` нужен для упорядоченного вывода примера: сами операции возвращают множества.

Ещё один пример — непересекающиеся составы персонажей:

```python
l4d1 = {"Bill", "Zoey", "Louis", "Francis"}
l4d2 = {"Coach", "Ellis", "Nick", "Rochelle"}
print(len(l4d1 | l4d2), l4d1 & l4d2)  # 8 set()
```

Пустое множество печатается как `set()`: запись `{}` создаёт пустой словарь.

## Представления ключей и пар словаря

Сравнивать можно не только отдельные множества, но и ключи или пары словарей:

```python
before = {"Portal": 9.99, "Portal 2": 9.99, "Left 4 Dead 2": 9.99}
after = {"Portal": 1.99, "Portal 2": 9.99, "Left 4 Dead 2": 1.99}

print(sorted(before.keys() & after.keys()))
# ['Left 4 Dead 2', 'Portal', 'Portal 2']
print(sorted(before.items() - after.items()))
# [('Left 4 Dead 2', 9.99), ('Portal', 9.99)]
```

Пересечение `keys()` отвечает, какие названия есть в обоих словарях. Разность `items()` сопоставляет пары `(ключ, значение)`: у двух игр прежняя пара с ценой 9.99 отсутствует в `after`. Здесь состав ключей одинаков, поэтому результат обозначает изменение цен. В общем случае прежняя пара может пропасть и из-за удаления самого ключа.

Ключи хешируемы по определению словаря; для приведённой операции над парами хешируемы также значения-цены. Если значения — списки, такие пары нельзя без оговорок использовать как элементы множества. [Уточнение по документации представлений словаря](https://docs.python.org/3.14/library/stdtypes.html#dictionary-view-objects).

## Три способа спросить о ключе

```python
from collections import defaultdict

library = {"Half-Life": 12, "Half-Life 2": 30}
print(library.get("Half-Life 3"))  # None

hours = defaultdict(int)
print(hours.get("Half-Life 3"), "Half-Life 3" in hours)  # None False
print(hours["Half-Life 3"], "Half-Life 3" in hours)      # 0 True

try:
    library["Half-Life 3"]
except KeyError as error:
    print("KeyError:", error)  # KeyError: 'Half-Life 3'
```

| Выражение | Обычный `dict`, если ключа нет | Создаёт запись |
|---|---|---|
| `key in d` | `False` | Нет |
| `d.get(key)` | `None` | Нет |
| `d[key]` | `KeyError` | Нет |
| `hours[key]` для `defaultdict(int)` | Значение фабрики `int()`, то есть 0 | Да |

У `defaultdict` обращение через `[]` при отсутствии ключа вызывает фабрику и сохраняет полученное значение. Метод `get` эту фабрику не вызывает. Поэтому чтение через `[]` может менять состав `defaultdict`, даже если в коде нет явного присваивания.

## Ноль и отсутствие записи

```python
hours = {"Portal 2": 0, "Dota 2": 1200}
for title in ["Portal 2", "Half-Life: Alyx"]:
    if hours.get(title):
        print(title, "играл")
    else:
        print(title, "не играл?")
print("Portal 2" in hours, "Half-Life: Alyx" in hours)  # True False
```

Обе итерации попадают в `else`: 0 и `None` ложны в логическом контексте. Но первая запись есть, вторая отсутствует. Если требуется наличие, использовать `title in hours`; `if hours.get(title)` проверяет истинность найденного значения.

Иллюстрация источника с файлом учёта Steam показывает раздел `apps`, где ключи — строковые `app id`, а `Playtime` — минуты. Для записи `"240"` поле `"Playtime" "30"` означает 0.5 часа; у `"440"` приведены `"Playtime" "53"` и `"LastPlayed" "1632853696"`, у `"240"` — `"LastPlayed" "1425052068"`. Игры Condition Zero с номером 80 в показанном фрагменте нет. Отсутствие записи нельзя автоматически считать явной записью нулевого времени. Это разбор конкретного формата на слайде, а не обещание неизменности файлов приложения.

## Порядок словаря и множества

```python
recent = {"Portal": 1, "Dota 2": 2, "Half-Life 2": 3}
recent["Portal"] = 4
print(list(recent))  # ['Portal', 'Dota 2', 'Half-Life 2']
print(list({"Portal", "Dota 2", "Half-Life 2", "Left 4 Dead 2"}))
```

Словарь сохраняет порядок вставки ключей; обновление значения уже существующего ключа не перемещает его. Это гарантия языка начиная с Python 3.7. Для множества порядок вставки не гарантирован: конкретный вывод второго `print` из слайда не нужно воспроизводить как установленную последовательность. [Порядок словаря в документации Python](https://docs.python.org/3.14/library/stdtypes.html#mapping-types-dict).

## Изменение состава во время обхода

```python
lots = {1: "Arms of Desolation", 2: "Magus Apex", 3: "Kilowatt Case"}
try:
    for lot_id in lots:
        if lot_id == 2:
            del lots[lot_id]
except RuntimeError as error:
    print("RuntimeError:", error)
print(lots)
```

В показанном запуске получаем `RuntimeError: dictionary changed size during iteration`, а словарь уже изменён: `{1: 'Arms of Desolation', 3: 'Kilowatt Case'}`. Исключение не отменяет выполненное удаление.

Не следует добавлять и удалять ключи словаря, по которому идёт обход: это может вызвать ошибку или нарушить полноту обхода. Вариант из лекции — обходить отдельный список ключей:

```python
for lot_id in list(lots):
    if lot_id == 2:
        del lots[lot_id]
```

Список фиксирует набор ключей для итерации, а удаление происходит в исходном словаре. [Уточнение поведения итерации](https://docs.python.org/3.14/library/stdtypes.html#dictionary-view-objects).

## Один список в dict.fromkeys

```python
wishlists = dict.fromkeys(["Gordon", "Chell"], [])
wishlists["Gordon"].append("Half-Life 3")
print(wishlists)
# {'Gordon': ['Half-Life 3'], 'Chell': ['Half-Life 3']}
```

Выражение `[]` создаёт один список. `fromkeys` помещает ссылку на него под каждый ключ, поэтому изменение через `"Gordon"` видно через `"Chell"`. Разные ключи не означают независимых объектов значений. Механизм общий с [[Копирование объектов|поверхностным копированием]] и [[Python — значения по умолчанию|общими изменяемыми значениями по умолчанию]].

## Counter подсчитывает вхождения

```python
from collections import Counter

friends = [
    {"Dota 2", "Portal 2"},
    {"Portal 2", "Team Fortress 2"},
    {"Portal 2", "Dota 2"},
]
counts = Counter()
for library in friends:
    counts.update(library)
print(counts.most_common(2))  # [('Portal 2', 3), ('Dota 2', 2)]
```

`update` прибавляет по одному за каждый встреченный элемент. Поскольку библиотека каждого друга — множество, одна игра учитывается не более одного раза на друга. `most_common(2)` возвращает две самые частые игры с их количествами.

## Строковые ключи JSON

```python
import json

answer = '{"730": {"success": true, "data": {"name": "Counter-Strike 2"}}}'
data = json.loads(answer)
print(list(data))                         # ['730']
print("730" in data, 730 in data)         # True False
print(data["730"]["data"]["name"])      # Counter-Strike 2
```

Имена полей объекта JSON — строки. После разбора `"730"` остаётся строковым ключом Python, даже если выглядит как число. Целое 730 — другой объект и не находит эту запись. Цепочка обращений сначала выбирает приложение, затем `data`, затем `name`.
