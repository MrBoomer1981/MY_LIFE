# Python — время жизни и сборка мусора

> [!abstract] Суть
> Объект живёт, пока его удерживают нужные программе связи. В CPython подсчёт ссылок дополняется сборщиком недостижимых циклов, а слабая ссылка сама не удерживает объект.

## Граф объектов и подсчёт ссылок

Объекты ссылаются друг на друга и образуют граф. Удаление имени снимает одну связь, но не уничтожает объект, если он остаётся доступным через другие имена или контейнеры. В обычной модели CPython счётчик отражает сильные ссылки; при обнулении освобождаются многие объекты. Немедленное уничтожение не является общей гарантией языка Python, а особенности версии и сборки CPython могут менять детали.

В традиционном представлении заголовок `PyObject` содержит счётчик ссылок и указатель на тип; это описание реализации, а не полного содержимого любого объекта. `sys.getrefcount(obj)` позволяет наблюдать счётчик, но сам вызов обычно добавляет временную ссылку.

## Почему циклы требуют отдельной сборки

```python
a = []
a.append(a)
del a
```

После удаления внешнего имени список всё ещё удерживает ссылку на себя. Один подсчёт ссылок не распознаёт, что цикл недостижим из программы. Сборщик `gc` ищет такие структуры. Пока на цикл ссылаются извне, он жив; после исчезновения внешних связей точный момент освобождения нельзя определять по одному `del`.

Концептуальная схема алгоритма из лекции:

1. Для проверяемой группы создаются временные значения счётчиков, в источнике названные `gc_refs`.
2. Из них вычитаются ссылки, приходящие от объектов самой группы.
3. Положительный остаток указывает на связи снаружи. От этих объектов обходят граф: всё достижимое сохраняется.
4. Оставшаяся недостижимая часть может быть освобождена.

Нулевой временный счётчик сам по себе ещё не означает мусор: к объекту может вести путь через другой живой объект группы. Это объяснение принципа, а не обещание неизменного внутреннего устройства всех версий CPython.

## Поколения и отслеживание

Поколения уменьшают стоимость обходов: новые объекты проверяются чаще, пережившие сборки — реже. В исходном примере `gc.get_threshold()` возвращает `(700, 10, 10)`. Это конфигурация показанной версии, а не универсальные значения. Число и обработка поколений, пороги и правила запуска зависят от версии и сборки CPython.

`gc.is_tracked(obj)` показывает, отслеживается ли объект циклическим сборщиком. В примерах PDF числа и строки не отслеживаются, список и словарь со списком — отслеживаются. Состояние кортежей и словарей может зависеть от оптимизаций и уже прошедших сборок. Поэтому результаты для `(1, 2)`, `{"a": 1}` и `(1, [])` не следует превращать в неизменную таблицу для любого запуска. Подсчёт ссылок и отслеживание циклов — разные механизмы.

## Слабые ссылки

```python
import weakref

cache = weakref.ref(g)
# cache() is g, пока объект жив

del g
# cache() is None, когда сильных ссылок больше нет и объект освобождён
```

Пример предполагает, что `g` поддерживает слабые ссылки и после `del g` не остаётся других сильных связей. Вызов слабой ссылки возвращает объект либо `None`, если он уже уничтожен. В отличие от обычной сильной ссылки, она не продлевает ему жизнь. Это полезно для кэша, который не должен удерживать объект сам по себе.

Обычные связи, циклы сильных связей и слабые связи нужно различать: цикл не является отдельным типом ссылки, это форма графа.
