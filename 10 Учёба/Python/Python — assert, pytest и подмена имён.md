# Python — assert, pytest и подмена имён

> [!abstract] Суть
> Диагностика тестов использует преобразование кода, а подмена зависимости действует там, где код ищет имя. Проверки `assert` зависят от режима запуска.

## assert и оптимизация

При `python -O` инструкции обычного `assert` исключаются из исполняемого кода. Поэтому проверку обязательных входных условий реализуют явным условием и исключением, например `if ...: raise ValueError(...)`, а не рассчитывают на `assert`.

## Почему pytest объясняет выражение

`pytest` переписывает AST тестовых модулей при импорте через `AssertionRewritingHook` в `sys.meta_path`. Значения частей выражения сохраняются во временных переменных, и сообщение может показывать не только неравенство, но и происхождение промежуточных значений, например `assert 13 == 12` и `where 13 = damage([6, 4], 3)`.

В источнике временные имена имеют вид `@py_assert...`: `@` недопустим в обычном идентификаторе исходного Python, поэтому такие имена не совпадут с пользовательскими. Различия в выводе локальных значений и глобальных имён отражают устройство диагностического представления, а не общий закон языка.

В кэше переписанных `.pyc` присутствует метка версии pytest; `-pytest-9.1.1` в PDF — частный пример, не постоянное имя. Для вспомогательного модуля можно заранее вызвать `pytest.register_assert_rewrite("helpers")`, например в `conftest.py`, до импорта самого модуля.

## mock.patch и место поиска

```python
# attack_a.py
import random

def attack():
    return random.randint(1, 20)
```

```python
# attack_b.py
from random import randint

def attack():
    return randint(1, 20)
```

В первом варианте при вызове читается атрибут модуля `random`. Во втором импорт уже создал отдельную глобальную связь `attack_b.randint`.

```python
from unittest.mock import patch

with patch("random.randint", return_value=20):
    attack_a.attack()  # 20
    attack_b.attack()  # прежняя импортированная функция

with patch("attack_b.randint", return_value=20):
    attack_b.attack()  # 20
```

Пример предполагает, что модули импортированы до подмены. Правило — подменять там, где имя ищет проверяемый код, а не обязательно там, где функция определена. Прежняя функция во втором модуле тоже может случайно вернуть 20: «подмена не сработала» не означает обязательного другого числа.

## Мутационное тестирование

В примере изменение AST заменяет `>=` на `>`. Если тесты остаются успешными, мутант «выжил»: набор не различает исходное и изменённое поведение. Для сравнения `hits(12, 12)` это указывает на непроверенную границу равенства. Здесь сохранено объяснение метода, без задания писать тесты.
