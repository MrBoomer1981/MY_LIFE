# Python — значения по умолчанию

> [!abstract] Суть
> Значение по умолчанию вычисляется при выполнении определения функции и сохраняет ссылку на объект. Новый список появляется при выполнении `[]`, а не автоматически при вызове.

## Когда вычисляется выражение

В `def wild(level=random.randint(1, 100))` случайный уровень выбирается при выполнении `def`. Последующие вызовы без аргумента используют сохранённое число. Аналогично `def enter(monster, log=prepare_log())` вызывает `prepare_log()` во время определения: если она печатает `PREPARE`, а следующая строка модуля — `READY`, вывод `PREPARE` появляется первым, до вызова `enter`.

Значения для позиционных параметров хранятся в `fn.__defaults__`; в примере `enter.__defaults__[0]` содержит журнал. Если функция возвращает этот журнал, то результаты двух вызовов и значение по умолчанию — один объект: `one is two is enter.__defaults__[0]`.

## Общий изменяемый объект

```python
def add_to_party(pokemon, party=[]):
    party.append(pokemon)
    return party

ash = add_to_party("Pikachu")
misty = add_to_party("Staryu")
# ash is misty: True
# оба имени видят ['Pikachu', 'Staryu']
```

Список создан один раз при определении. Если нужен новый объект для каждого вызова без переданного списка, создание переносят в тело:

```python
def add_to_party(pokemon, party=None):
    if party is None:
        party = []
    party.append(pokemon)
    return party
```

Такой же принцип применяется к журналам `enter(monster, log=None)` и фабрикам журналов: новый объект создаётся на том уровне, где нужна независимость.

## Почему or подменяет пустой журнал

```python
def enter(monster, log=None):
    if log is None:
        log = []
    log.append(monster)
    return log

provided = []
result = enter("Roz", provided)
# result is provided: True
```

Замена условия на `log = log or []` нарушает это свойство: переданный пустой список ложен и заменяется другим. Проверка `is None` сохраняет явно переданный контейнер, даже пустой.

## Вложенный def и фабрики

Если `def` с `log=[]` находится внутри `make_station`, каждый вызов фабрики заново выполняет это определение и получает собственный список. Вызовы одной возвращённой функции продолжают делить его: `a("Sulley")`, затем `a("Mike")` накапливают `['Sulley', 'Mike']`; отдельная функция `b("Roz")` содержит `['Roz']`.

Это отличается от списка в значении по умолчанию самой фабрики: такой список создаётся при определении фабрики и может оказаться общим между её вызовами. Выражение `[]` должно выполняться там, где нужна новая независимая структура.

## Сохраняется ссылка, а не имя и не копия

```python
log = []
read = lambda saved=log: saved
log.append("A7")
log = ["B8"]
read()  # ['A7']
```

Дефолт удерживает первый список. Его изменение видно через сохранённую ссылку, а перепривязка имени `log` не меняет `saved`. По той же причине `lambda s=s: s` фиксирует ссылку на текущий объект при создании каждой функции, не создавая глубокую копию.
