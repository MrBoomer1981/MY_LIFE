# Python — области видимости и функции

> [!abstract] Суть
> Поведение функции зависит от трёх моментов: анализа кода, выполнения определения функции и конкретного вызова. Смешение этих моментов объясняет многие неожиданные результаты.

## Области видимости

Для обычного тела функции модель LEGB различает локальные имена, имена объемлющих функций, глобальные имена модуля и встроенные имена. Это полезная модель поиска, но она не описывает все особенности классов и специальных областей видимости.

Присваивание имени в теле функции обычно делает его локальным во всём этом теле, если не указаны `global` или `nonlocal`. Поэтому чтение такого имени до присваивания не переключается автоматически на одноимённую глобальную переменную, а приводит к `UnboundLocalError`.

`global` связывает операции с пространством имён модуля, а `nonlocal` — с существующей связью в объемлющей функции. Функция использует глобальные имена своего модуля, даже если вызвана из другого.

## Функция как объект

Выполнение `def` создаёт объект функции и связывает с ним имя. Этот объект можно передавать, сохранять в контейнере и возвращать из другой функции. Каждый вызов создаёт свой контекст локальных переменных. Если выполнение дошло до конца без явного результата, возвращается `None`.

Передача аргумента связывает параметр с объектом. Изменение переданного списка может быть видно вызывающему коду; перепривязка локального параметра к другому списку сама по себе не меняет имя у вызывающего.

## Замыкания

Замыкание сохраняет доступ к связям из внешней функции. Оно не обязано фиксировать значение на момент создания: несколько функций могут использовать одну общую ячейку и видеть её последующее содержимое.

Поэтому функции, созданные в одном цикле и читающие общую переменную цикла при вызове, обычно видят её последнее значение. Значение по умолчанию может фиксировать текущую ссылку при создании функции, но это всё ещё ссылка на объект, а не глубокая копия.

## Значения по умолчанию

Выражения значений по умолчанию вычисляются при выполнении `def`, а не при каждом вызове. Если результатом был список, последующие вызовы без соответствующего аргумента получают тот же список.

Если же новый список создаётся в теле функции при каждом вызове, у вызовов появляются отдельные объекты. При вложенном `def` повторный вызов внешней функции снова выполняет определение и создаёт новый комплект значений по умолчанию.

## Сигнатура

Параметры бывают только позиционными, позиционными или именованными, собирающими лишние позиционные аргументы (`*args`), только именованными и собирающими лишние именованные аргументы (`**kwargs`). Сигнатура определяет допустимую форму вызова.

Допустимая форма не гарантирует допустимость содержимого аргументов. Аннотация типа сама по себе не осуществляет проверку значения при вызове. Это разные уровни: связывание аргументов, описание ожидаемых типов и поведение тела функции.

## Имена и атрибуты

Поиск имени и получение `obj.attribute` — разные механизмы. Поиск атрибута может учитывать дескрипторы, словарь экземпляра и порядок разрешения методов MRO. Поэтому упрощение «сначала всегда словарь экземпляра» не универсально: дескрипторы данных при стандартном доступе имеют приоритет.

## LEGB и пространства функции

| Уровень | Где находятся связи | Пример из источника |
|---|---|---|
| L — Local | Локальный контекст текущего вызова | `roll` в `cast(roll)` |
| E — Enclosing | Ячейки объемлющих функций | `base` из `make_spell(base)` |
| G — Global | Пространство родного модуля | `spell_mod = 3` |
| B — Builtins | Встроенные имена | `len`, `sum`, `print` |

Если в модуле выполнить `sum = 20`, вызов `sum(rolls)` пытается вызвать число и даёт `TypeError`. После удаления этой глобальной связи `del sum` снова становится доступна встроенная функция.

Функция `greet`, импортированная из `pallet_town`, продолжает читать глобальные имена в исходном модуле: `greet.__globals__ is pallet_town.__dict__`. Поэтому присваивание `REGION = "Johto"` в `main.py` не меняет её исходное глобальное значение `"Kanto"`.

Словари используются и самим Python для организации пространств имён. Бонусный блок `L08.pdf` сопоставляет три объекта: `globals()` возвращает словарь глобальных имён текущего модуля, `модуль.__dict__` хранит пространство имён модуля, а `sys.modules` — словарь загруженных модулей по их именам. Это разные словари с разным назначением. Принципы доступа по ключу: [[Python — словари, множества и отсутствующие значения]].

## Объект функции и кадр вызова

| Атрибут | Значение |
|---|---|
| `__name__` | Имя функции |
| `__doc__` | Строка документации |
| `__module__` | Имя модуля определения |
| `__code__` | Объект кода |
| `__closure__` | Кортеж ячеек замыкания либо `None` |
| `__globals__` | Словарь глобальных имён родного модуля |
| `__builtins__` | Связанное встроенное пространство в поддерживающих атрибут версиях |
| `__defaults__` | Позиционные значения по умолчанию |

При выполнении `def` объект функции получает код, ссылки на окружение и вычисленные значения по умолчанию. При каждом вызове появляется контекст локальных переменных. В примере `battle()` с `hp = 100; hp -= 30` каждый обычный независимый вызов снова получает 70. Локальное `hp` не становится атрибутом функции: `hasattr(battle, "hp")` ложно. Текущий кадр и его локальные значения можно наблюдать через `inspect.currentframe().f_locals`.

`return` немедленно завершает выполнение. `return hp, hp > 0` возвращает один кортеж; вызывающий может распаковать его как `hp, alive = fight(35, 10)`. Функцию можно положить в словарь и вызывать по ключу, как `moves["ember"]("Pidgey")`.

## Lambda и позднее чтение ячейки

`lambda p: p["level"]` создаёт объект функции с именем `<lambda>`. Как и функция, созданная через `def`, он имеет код и окружение, но не обязан иметь буквально тот же байткод. Пример применения — `sorted(team, key=lambda p: p["level"])`. В трассировке будет `<lambda>`; если функции нужно устойчивое имя, в источнике рекомендован `def` (PEP 8, правило ruff E731).

```python
stages = [lambda: i for i in range(3)]
[f() for f in stages]  # [2, 2, 2]
# stages[0].__closure__[0] is stages[1].__closure__[0]
```

Список `stages` содержит функции, а не числа. Числа получаются после вызова: функции читают одну общую ячейку, в которой осталось 2. При `lambda i=i: i` текущий объект сохраняется в значении по умолчанию; у таких функций из примера `__closure__` равен `None`, а собственное значение находится в `__defaults__`.

## Изменение ячейки через nonlocal

```python
def pokedex():
    caught = 0
    def catch(name):
        nonlocal caught
        caught += 1
        return f"{name}: поймано {caught}"
    return catch

catch = pokedex()
catch("Pidgey")   # 'Pidgey: поймано 1'
catch("Rattata")  # 'Rattata: поймано 2'
```

Одна возвращённая функция сохраняет общую для своих вызовов ячейку. Каждый новый вызов фабрики создаёт другую ячейку: аналогичные счётчики `mike` и `sulley` независимы, первый может вернуть 1 и 2, второй — начать с 1.
