# Python — хешируемость и равенство ключей

> [!abstract] Суть
> Ключ словаря и элемент множества должны быть хешируемыми: их хеш стабилен, а равным объектам соответствует одинаковый хеш. Совпадение хешей само по себе не означает равенства.

## Два требования

Для корректного использования ключа в хеш-таблице необходимо:

1. Если $a=b$ по `==`, то $\operatorname{hash}(a)=\operatorname{hash}(b)$.
2. Хеш не меняется за время жизни объекта; в частности, нельзя менять его, пока объект используется как ключ. Поведение равенства тоже должно оставаться согласованным с ключом.

Хеш сначала определяет место поиска, после чего таблица сопоставляет кандидатов с искомым ключом. Из одинакового хеша равенство не следует:

```python
print(hash(-1), hash(-2), -1 == -2)  # -2 -2 False
reviews = {-1: "не рекомендую", -2: "рекомендую"}
print(len(reviews))  # 2
```

Это пример двух разных ключей с одним хешем. Связь с размещением в таблице: [[Python — поиск и устройство хеш-таблицы]].

## 1, 1.0 и True — один ключ

```python
one, one_float = 1, 1.0
print(one == one_float == True)                 # True
print(hash(one), hash(one_float), hash(True))   # 1 1 1
print(one is one_float)                        # False

review = {
    True: "рекомендую",
    1: "одна звезда",
    1.0: "одна звезда из пяти",
}
print(review)                # {True: 'одна звезда из пяти'}
print(len({1, 1.0, True}))    # 1
```

Объекты разных типов могут быть равны. Эти три числовых значения имеют равные хеши, поэтому последующие присваивания обновляют одну запись. В данном примере объект первого ключа `True` остаётся в словаре, значение берётся из последнего присваивания. Во множестве остаётся один элемент. Оператор `is` отвечает за тождественность объектов и не заменяет `==`.

## Почему изменение ключа разрушает поиск

Лекция моделирует ошибку с помощью собственной таблицы, которая допускает список в качестве ключа:

```python
def toy_hash(words):
    return sum(ord(letter) for word in words for letter in word)

def put(table, key, value):
    table[toy_hash(key) % len(table)].append([key, value])

def get(table, key):
    for pair in table[toy_hash(key) % len(table)]:
        if pair[0] == key:
            return pair[1]
    return None

table = [[] for _ in range(8)]
disguise = ["Engineer", "RED"]
put(table, disguise, "Spy")
print(toy_hash(disguise) % 8, get(table, ["Engineer", "RED"]))
# 0 Spy

disguise[0] = "Medic"
print(toy_hash(disguise) % 8, get(table, ["Medic", "RED"]))
# 5 None
print(get(table, ["Engineer", "RED"]))  # None
print(table[0])                        # [[['Medic', 'RED'], 'Spy']]
```

В таблице хранится ссылка на список. После его изменения запись физически остаётся в ящике 0, но новый хеш ведёт в ящик 5. По старому содержимому запись тоже не находится: лежащий в ящике 0 список теперь другой по значению. Запись существует, но нормальный путь поиска потерян.

Настоящий `dict` не позволяет непосредственно использовать список как ключ:

```python
spies = {}
# spies[["Engineer", "RED"]] = "Spy"  # TypeError: список нехешируем

spies[("Engineer", "RED")] = "Spy"
print(spies)  # {('Engineer', 'RED'): 'Spy'}

# spies[("Engineer", ["RED"])] = "Spy"  # TypeError из-за вложенного списка
```

Точная формулировка сообщения `TypeError` зависит от версии Python; причина одинакова — нехешируемый ключ или его компонент.

## Хешируемость составного объекта

| Объект из лекции | Допустим как ключ | Причина |
|---|---|---|
| `730` | Да | Целое число хешируемо |
| `"Portal 2"` | Да | Строка хешируема |
| `("AK-47", "Redline", "Field-Tested")` | Да | Все элементы кортежа хешируемы |
| `["Bill", "Zoey"]` | Нет | Список нехешируем |
| `frozenset({"Bill", "Zoey"})` | Да | Неизменяемое множество хешируемых строк |
| `("Coach", ["Ellis"])` | Нет | Неизменяемость самого кортежа не делает вложенный список хешируемым |
| `{"app_id": 220}` | Нет | Словарь нехешируем |
| `None` | Да | Объект хешируем |

В источнике эти варианты проверяются вызовом `hash(key)` с перехватом `TypeError`; последовательность ответов: да, да, да, нет, да, нет, нет, да. Требования относятся к ключам, а значения словаря могут быть списками, словарями и другими нехешируемыми объектами.

Заголовок слайда «Ключ неизменяем целиком» — упрощение. Корректное общее требование — **хешируемость**, а для кортежа — хешируемость всех его элементов. Хешируемость не означает неизменяемости любого состояния объекта: например, обычные экземпляры пользовательских классов по умолчанию могут быть хешируемыми по идентичности. Это уточнение границы формулировки лекции, а не отдельная тема реализации классов. [Определение в документации Python](https://docs.python.org/3.14/glossary.html#term-hashable).

## Равные экземпляры во множестве

```python
def make_cube(*marks):
    return tuple(["кубик", "50 кг", *marks])

storage = make_cube()
other = make_cube()
companion = make_cube("сердечко")
print(storage == other, storage is other)  # True False
print(len({storage, other}))              # 1
print(len({storage, other, companion}))   # 2
```

В этом примере два отдельно созданных равных кортежа представляют один элемент множества. Дополнительная метка меняет значение кортежа и позволяет хранить второй элемент. Множество устраняет равные значения, а не только повторные ссылки на один объект.

## Хеш не является постоянным внешним идентификатором

В лекции хеш длинной строки остаётся целым числом, а не растёт вместе с её длиной. Численный предел в демонстрации относится к разрядности используемой реализации. В CPython возвращаемый хеш ограничен размером `Py_ssize_t`; 64-битный результат не следует объявлять гарантией всех платформ. [Документация `__hash__`](https://docs.python.org/3.12/reference/datamodel.html#object.__hash__).

Для строк хеш стабилен в пределах процесса, но обычно рандомизирован между запусками. В источнике при `PYTHONHASHSEED` 1, 2 и 3 выражение `hash("Portal") % 8` даёт соответственно 3, 6 и 1, тогда как `hash(400)` остаётся 400. Конкретные остатки иллюстрируют запуск, а не универсальные результаты для любой версии. По этой причине `hash(title)` нельзя сохранять как неизменный идентификатор предмета между запусками. [Рандомизация хешей строк](https://docs.python.org/3.13/reference/datamodel.html#object.__hash__).
