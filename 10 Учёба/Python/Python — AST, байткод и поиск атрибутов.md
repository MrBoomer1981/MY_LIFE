# Python — AST, байткод и поиск атрибутов

> [!abstract] Суть
> До выполнения компилятор определяет структуру выражений и категории имён. Получение атрибута объекта происходит по отдельным правилам во время обращения.

## От текста к выполнению

Обобщённый путь CPython:

```mermaid
flowchart LR
    Source[Исходный текст] --> Tokens[Токены] --> AST[AST: дерево синтаксиса]
    AST --> Symbols[Таблица имён] --> Bytecode[Байткод] --> Run[Выполнение]
```

Анализ блока предшествует исполнению его инструкций. Это не значит, что все возможные определения программы исполняются до запуска: вложенный `def` выполняется при достижении соответствующей строки.

## Структура AST

```python
import ast

tree = ast.parse("damage = base * 2 + bonus")
print(ast.dump(tree.body[0], indent=2))
```

В дереве `Assign` содержит цель `Name(id='damage', ctx=Store())` и выражение `BinOp`. Внутренний `BinOp` умножает `base` на `Constant(value=2)`, внешний прибавляет `bonus`. `Name` представляет имя, `Constant` — константу; `Store` означает запись, `Load` — чтение.

Форма дерева отражает группировку и приоритет операций: `base * 2` — операнд внешнего сложения. Обобщение «глубже всегда раньше» неверно для всех конструкций: порядок также зависит от правил узлов и короткого замыкания. Лишние скобки и обычные комментарии в AST не сохраняются.

| Средство | Назначение |
|---|---|
| `ast.dump(tree, indent=2)` | Представить дерево текстом |
| `ast.unparse(tree)` | Получить исходный текст с эквивалентной структурой |
| `ast.walk(tree)` | Обойти узлы, не обещая порядка выполнения |
| `compile(tree, "<name>", "exec")` | Получить исполняемый объект кода |
| `exec(code, ns)` | Выполнить код в заданном пространстве имён |

В примере «нерфа» замена узла `Mult` на `FloorDiv` превращает вычисление в `damage = base // 2 + bonus`. Меняется дерево, из которого компилируют новый код; файл исходника не обязательно меняется. Код здесь обрабатывается как данные.

## Решение о локальности и байткод

```python
spell_slots = 3

def cast_fireball():
    print(spell_slots)
    spell_slots -= 1
```

При вызове возникает `UnboundLocalError`: присваивание делает `spell_slots` локальным во всём теле, а чтение выполняется до локального присваивания. Внешнее значение 3 не используется как запасной вариант. `global` и `nonlocal` изменяют решение о пространстве записи. Подробности — [[Python — области видимости и функции]].

| Атрибут объекта кода | Содержание |
|---|---|
| `fn.__code__.co_varnames` | Имена локальных переменных и параметров |
| `fn.__code__.co_names` | Имена, используемые инструкциями, в том числе глобальные и имена атрибутов |
| `fn.__code__.co_freevars` | Имена свободных переменных из объемлющих функций |

`dis` показывает байткод. `LOAD_GLOBAL` ищет имя в глобальном и встроенном пространствах; показанный в PDF `LOAD_FAST_CHECK` читает локальную переменную с проверкой инициализации. Конкретные инструкции меняются между версиями CPython. `symtable` показывает классификацию символов через `is_global()` и `is_local()`.

## Атрибуты, типы и MRO

У любого значения есть тип, включая `None` и функции. LEGB описывает поиск обычных имён, а `obj.x` — получение атрибута. При стандартном механизме важны словарь экземпляра, атрибуты класса и порядок MRO (Method Resolution Order), заданный `type(obj).__mro__`.

Упрощённое правило из PDF «сначала всегда `obj.__dict__`, потом класс» требует исправления: дескриптор данных класса имеет приоритет перед словарём экземпляра. После него учитываются данные экземпляра и остальные атрибуты класса с учётом MRO. Пользовательские механизмы доступа могут менять поведение; не каждый объект имеет `__dict__`. При неуспехе поиска обычно возникает `AttributeError`.

```python
bool.__mro__  # (bool, int, object)
True + True  # 2
sum([True, False, True])  # 2
```

`bool` — подкласс `int`, поэтому булевы значения участвуют в этих числовых операциях. Компилятор заранее классифицирует имена; значения имён и атрибутов могут меняться во время работы.

Продолжение: [[Python — assert, pytest и подмена имён]]. Проверка исправленного порядка доступа: [модель данных Python](https://docs.python.org/3.11/reference/datamodel.html#invoking-descriptors).
