# Асимптотика — рост времени и памяти

[[Алгоритмы и C]]

Асимптотика описывает, как меняются затраты при росте входа. Сначала выбирают размер входа, модель стоимости и рассматриваемый случай, затем оценивают соответствующую функцию. Обозначение границы и выбор лучшего, худшего или среднего случая — разные вещи.

## Что измеряет оценка

Временная сложность — число существенных операций; пространственная — необходимая память. Отдельно различают всю память и дополнительную сверх входа. Для приведённых массивов $n$ — число элементов. Если длина ключей или размер элемента тоже растут, их стоимость нельзя скрывать в постоянной.

При фиксированной разрядности доступ по индексу, сложение и сравнение машинных чисел считаются $O(1)$. Полный проход из $n$ таких шагов — $\Theta(n)$; два независимых вложенных полных прохода — $\Theta(n^2)$. На списке получение $i$-го элемента требует обхода, поэтому цикл с `list[i]` может добавить ещё один множитель.

**Уточнение слайда `int arr[N] — O(N)`:** массив действительно занимает $\Theta(n)$ памяти; время объявления не равно автоматически времени заполнения. Инициализация всех элементов требует $\Theta(n)$ записей. Размер фиксированного массива из десяти элементов не растёт вместе с $n$.

## O, Ω, Θ, o и ω

Для неотрицательных при достаточно больших $n$ функций $f,g$ с $g(n)>0$:

| Запись | Точное условие |
|---|---|
| $f\in O(g)$ | Существуют $C>0,n_0$: $f(n)\le Cg(n)$ для всех $n\ge n_0$ |
| $f\in\Omega(g)$ | Существуют $c>0,n_0$: $f(n)\ge cg(n)$ для всех $n\ge n_0$ |
| $f\in\Theta(g)$ | Одновременно $f\in O(g)$ и $f\in\Omega(g)$ |
| $f\in o(g)$ | Для любого $\varepsilon>0$ при всех достаточно больших $n$ выполнено $f(n)\le\varepsilon g(n)$ |
| $f\in\omega(g)$ | Для любого $C>0$ при всех достаточно больших $n$ выполнено $f(n)\ge Cg(n)$ |

Формальные условия — **дополнительное раскрытие** смыслов «верхняя», «нижняя», «точная» и «строгая» граница из лекции. Если предел отношения существует, $f=o(g)$ соответствует $f/g\to0$, а $f=\omega(g)$ — $f/g\to+\infty$.

**Уточнение таблицы лекции:** $O$ не означает по определению худший случай, $\Omega$ — лучший, $\Theta$ — средний. Каждое обозначение можно применить к уже выбранной функции: например, худшее время бинарного поиска $\Theta(\log n)$, лучшее $\Theta(1)$. Точная граница не является фразой «ровно столько секунд».

Примеры:
$$3n+7\in\Theta(n),\quad n\in o(n^2),\quad n^2\in\omega(n),$$
$$\log n\in o(n),\qquad\log n\in\omega(1).$$
Из $f\in\Theta(n)$ следует, что $f$ не принадлежит $o(n)$ и $\omega(n)$, но, например, $f\in o(n^2)$. Поэтому фраза слайда «малые o и ω оценить невозможно» относится только к сравнению именно с $n$, а не к отсутствию любых строгих оценок.

## Лучший, худший, ожидаемый и амортизированный случаи

Для множества входов размера $n$ лучший случай минимизирует время, худший максимизирует. Среднее или математическое ожидание требует распределения входов либо случайных решений алгоритма. Без распределения фраза «в среднем» не задаёт точную математическую модель.

Амортизированная оценка относится к последовательности операций: геометрически растущий `Vector` добавляет $n$ элементов за $O(n)$ суммарных переносов, хотя отдельное расширение может стоить $O(n)$. Это не случайный удачный вход. У хеш-таблицы дополнительно требуется анализ распределения хешей. Условное $O^*(1)$ лекции не следует использовать для смешения этих двух причин.

| Операция | Условие оценки |
|---|---|
| Индекс массива/Vector | $O(1)$ при постоянном размере элемента |
| Индекс списка | $O(n)$; первый узел доступен за $O(1)$ |
| Вставка в конец Vector | Амортизированно $O(1)$ при геометрическом росте |
| Вставка/удаление в конце списка | $O(1)$ только при нужных связях; односвязный без предшественника не удаляет хвост за $O(1)$ |
| Вставка в начало массива | $O(n)$ из-за сдвига |
| Поиск значения в неиндексированном массиве/списке | $O(n)$ |
| Поиск хеш-таблицы | Ожидаемо $O(1)$ при подходящем распределении и ограниченном заполнении; худший случай может быть линейным |

Полная таблица контейнеров: [[Динамический массив, список и стоимость операций]]. Прибавление единичной операции и при умножении постоянных множителей класс роста не меняется: $O(3n)=O(n)$, $O(3n^2)=O(n^2)$.

## Удаление повторений через просмотренные элементы

В лекции 9 сопоставлены два способа: линейно искать каждый очередной элемент во временном массиве `seen` либо хранить просмотренные ключи в `HashSet`.

Схема C-фрагмента с массивом:

```text
создать seen и output
для каждого item исходного Vector:
    если item ещё не найден в seen: добавить item в output
    добавить item в seen
освободить seen; вернуть output
```

Если все $n$ ключей различны, поиск просматривает $0,1,\ldots,n-1$ элементов:
$$\sum_{i=0}^{n-1}i=\frac{n(n-1)}2=\Theta(n^2).$$
Геометрический рост векторов не устраняет этот поиск. Если добавление реализовано с перевыделением на одно место, появится и дополнительная квадратичная стоимость; при обычном геометрическом росте суммарное добавление линейно.

С хеш-множеством:

```text
создать пустое множество seen и выходной Vector
для каждого item в порядке входа:
    если item отсутствует в seen:
        добавить item в output
        добавить item в seen
вернуть output; освободить seen
```

При ожидаемо постоянном поиске и вставке это $\Theta(n)$ ожидаемого времени и $O(n)$ дополнительной памяти. Выход сохраняет первые вхождения в исходном порядке. **Промежуточное доказательство:** перед обработкой позиции $i$ `seen` содержит ровно ключи уже обработанного префикса, а `output` — их первые появления. Проверка принадлежности либо сохраняет состояние для повторения, либо добавляет новый ключ, поддерживая инвариант.

**Расхождения исходных примеров.** Python-вариант с двойным циклом добавляет элемент, только если вообще нет равного на другой позиции, то есть оставляет значения с частотой один; второй вариант добавляет уже встречавшиеся элементы. Они не вычисляют один результат. Для `[1,2,3,1,2]` первая логика даёт `[3]`, вторая — `[1,2]`, а удаление повторений с сохранением первых вхождений — `[1,2,3]`. Это пояснение поведения опубликованного кода, а не новое задание.

В Python-слайде аннотация `seen: set[int]` сама не создаёт множество: нужна инициализация `seen = set()`, как и `duplicates = []`. В C-версии заранее выделенный `output` должен в итоге иметь длину числа уникальных ключей `insertIndex`, иначе останутся фиктивные элементы. «Рехешировать output» — неточное название: здесь нужен пересмотр размера/буфера обычного вектора. `vectorFree(seen)` не является корректным освобождением произвольного `HashSet`; оно требует собственного интерфейса. Обнуление буфера и освобождение вложенных записей также нельзя всегда считать $O(1)$ без анализа реализации.

## Графики роста и эксперименты

![[Измерение — малые массивы.png]]

На слайде с массивами 10 и 100 элементов различие двух реализаций почти не видно на выбранной шкале. Это не равенство классов роста.

![[Измерение — тысяча элементов.png]]

![[Измерение — сто тысяч элементов.png]]

Зелёная линия обозначает квадратичный алгоритм, красная — линейный. Вертикальная ось — время в секундах, горизонтальная подписана «количество итераций». При 1000 элементах разница достигает примерно сотых секунды, при 100000 — сотен секунд. Это данные/иллюстрации автора; условия измерений и исходные выборки не даны, графики не являются доказательством точной функции времени.

Модель слайда: если один элементарный шаг стоит $10^{-6}$ секунды, для $n=10^6$ линейный проход требует примерно $1$ секунду, $n^2$ шагов — $10^6$ секунд, то есть около $16667$ минут, $278$ часов, $11.6$ суток. Важно различать $10^6$ входных элементов и $10^{12}$ внутренних шагов: подпись про «миллион итераций» в квадратичном случае неточна.

![[Рост функций — общий график.png]]

![[Рост функций — полиномиальные оценки.png]]

Кривые сопоставляют $1,\log n,n,n\log n,n^2,2^n,n!$; вторая картинка приближает область полиномиальных функций. Оси исходника подписаны временем и числом итераций, но это условные масштабы функций, а не универсальные секунды. При больших $n$:
$$1\prec\log n\prec n\prec n\log n\prec n^2\prec2^n\prec n!,$$
где $f\prec g$ означает $f=o(g)$.

![[Асимптотика — постоянный множитель.png]]

Здесь обе оси логарифмические: прямые $3n$ и $n$ параллельны и различаются постоянным множителем, а $3n^2$ растёт быстрее. Это объясняет переход автора от $O(3n^2)$ к $O(3n)$ без превращения коэффициента 3 в самостоятельный класс.
