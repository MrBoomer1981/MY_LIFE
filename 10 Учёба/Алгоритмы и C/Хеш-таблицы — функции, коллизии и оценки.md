# Хеш-таблицы — функции, коллизии и оценки

[[Алгоритмы и C]]

Хеш-таблица преобразует ключ в номер небольшой ячейки. Разным ключам может соответствовать одна ячейка, поэтому нужны правило сравнения ключей и способ разрешать коллизии. Постоянное время операций требует условий на распределение хешей и заполнение таблицы.

## От прямой адресации к хешированию

В лекции 7 подсчитываются разные значения массива `[1, 10, 200, 1, 11, 10, 11]`: четыре различных значения — `1`, `10`, `200`, `11`. Для неотрицательных целых можно завести массив частот, где `counter[x]` хранит число появлений `x`, а затем посчитать положительные счётчики. Для максимума $M$ нужны $M+1$ ячеек, включая индекс $M$; время с обнулением и итоговым обходом $\Theta(n+M+1)$, память $\Theta(M+1)$.

**Уточнения исходного кода:** `max_value` без `+1` недостаточно; `sizeof(data_in)` при массиве с именем `vector` — несогласованное имя; `short` нельзя читать через `int *`. В API, копирующем данные по адресу, новое значение передают как адрес переменной. Счётчик должен вмещать частоту. Для отрицательных значений нужен сдвиг диапазона либо другое представление.

При универсуме $U=\{0,\ldots,m-1\}$ таблица прямой адресации хранит ключ $k$ прямо в `T[k]`:

```text
SEARCH(T, k): вернуть T[k]
INSERT(T, x): T[x.key] = x
DELETE(T, x): T[x.key] = EMPTY
```

При постоянном доступе по индексу операции стоят $\Theta(1)$, но память $\Theta(m)$, даже если реально занято $n\ll m$ мест.

![[Прямая адресация — ключи и ячейки.png]]

Слева показан весь универсум и небольшой набор реально используемых ключей; стрелки ведут в одноимённые ячейки справа. Большой разреженный диапазон делает такой массив затратным. Рисунок — из лекции 7.

Хеш-функция $h:U\to\{0,\ldots,m-1\}$ сжимает пространство ключей. **Коллизия** — равенство $h(k)=h(l)$ для разных $k\ne l$. Оно не означает равенства ключей: при поиске сравнивают сами ключи.

![[Хеширование — коллизия.png]]

Стрелки от разных исходных значений сходятся к одной ячейке. В частности, отрицательный ключ нельзя напрямую использовать как индекс неотрицательного массива. Это мотивирует единое правило преобразования ключей.

## Хеш-функции деления и умножения

Метод деления:
$$h(k)=k\bmod m.$$
В лекции рекомендуется простое $m$, далёкое от степени двойки: плохой выбор делителя способен подчеркнуть закономерности ключей. Это рекомендация для данного метода, а не обязательное условие любой хеш-таблицы.

**Дополнительное пояснение для C:** математический остаток для индекса берут в диапазоне $0,\ldots,m-1$. Знаковый `%` при отрицательном ключе может дать отрицательный результат; индекс нужно нормализовать и согласовать знаковые типы. Одного приведения отрицательного числа к `size_t` без анализа недостаточно для сохранения задуманного математического хеша.

Метод умножения:
$$h(k)=\left\lfloor m\{kA\}\right\rfloor,\qquad 0<A<1,\quad \{x\}=x-\lfloor x\rfloor.$$
В лекции предложено $A\approx(\sqrt5-1)/2\approx0.6180339887$. Выбор $m$ здесь менее чувствителен, чем в методе деления; качество зависит от $A$ и ключей. Под $kA\bmod1$ понимается дробная часть. Реализация с конечной точностью должна сохранять индекс в допустимом диапазоне.

## Метод цепочек и коэффициент заполнения

В каждой ячейке массива хранится цепочка записей с одинаковым хешем. Например, при $h(k)=k\bmod10$ ключи $1,11,21$ попадают в одну цепочку. Поиск сначала выбирает корзину, затем сравнивает ключи внутри неё. Новый ключ добавляется в цепочку, существующий ключ словаря обновляет своё значение.

![[Хеширование — цепочка.png]]

Стрелки от $1,11,21$ приходят в одну корзину; связи вниз ведут по её списку. Другие корзины остаются независимыми. Продолжение цепочки до $31,\ldots$ показывает, почему худший поиск может стать линейным.

$$\alpha=\frac nm,$$
где $n$ — число хранимых записей, $m$ — число корзин. Это **среднее число элементов в цепочке**. В цепочках допустимо $\alpha>1$; в открытой адресации при хранении всех записей в массиве необходимо $n\le m$.

**Уточнение слайда:** $\alpha<1$ не гарантирует редкость коллизий во всей таблице. При $n>m$ хотя бы одна коллизия неизбежна по принципу Дирихле, но и при $n<m$ их может быть много.

Простое равномерное хеширование предполагает одинаковую вероятность каждой корзины для каждого ключа и соответствующую независимость распределения ключей. Лекция подчёркивает: реальное распределение входов часто неизвестно, ключи могут зависеть друг от друга. Поэтому это модель анализа, а не автоматически выполненное свойство произвольной функции.

![[Хеширование — равномерное и нормальное распределения.png]]

На полях доказательства в лекции 8 сопоставлены колоколообразное нормальное и плоское равномерное распределения. Для предположения о корзинах требуется равномерность; это не предположение о нормальном распределении ключей. Высота на рисунке обозначает плотность/вероятностный профиль, ось X — значения случайной величины; частоты реальных ключей данным рисунком не измерены.

## Неуспешный поиск в цепочках

**Теорема из лекции 8.** При простом равномерном хешировании, постоянной стоимости вычисления хеша и сравнения ключей ожидаемое время неуспешного поиска в таблице с цепочками равно $\Theta(1+\alpha)$.

**Доказательство.** Если ключа нет, нужно пройти всю выбранную цепочку. Для каждого хранимого ключа $x_i$ введём индикатор $I_i$, равный $1$, если он попал в корзину запроса, и $0$ иначе. В равномерной модели $\mathbb E I_i=1/m$. Длина нужной цепочки $L=\sum_{i=1}^nI_i$, поэтому
$$\mathbb EL=\sum_{i=1}^n\mathbb EI_i=\frac nm=\alpha.$$
Постоянная работа вычисления хеша и выбора корзины даёт единицу, проход — ожидаемые $\alpha$ сравнений. Получаем $\Theta(1+\alpha)$. Индикаторное раскрытие — промежуточное пояснение к доказательству слайда.

## Успешный поиск в цепочках

**Теорема из лекции 8.** При простом равномерном хешировании, вставке новых ключей в начало цепочки и равновероятном выборе искомого ключа среди $n\ge1$ хранимых ожидаемое время успешного поиска равно $\Theta(1+\alpha)$.

**Доказательство.** Обозначим ключи в порядке вставки $x_1,\ldots,x_n$. Перед $x_i$ в цепочке находятся ключи, вставленные позже и попавшие в ту же корзину. Введём
$$X_{ij}=\mathbf1_{\{h(x_i)=h(x_j)\}},\qquad j>i.$$
Число проверенных элементов при поиске $x_i$ равно $1+\sum_{j=i+1}^nX_{ij}$. Усредняем по равновероятно выбранному $i$ и хешированию:
$$\begin{aligned}
\mathbb E C
&=\mathbb E\left[\frac1n\sum_{i=1}^n\left(1+\sum_{j=i+1}^nX_{ij}\right)\right]\\
&=\frac1n\sum_{i=1}^n\left(1+\sum_{j=i+1}^n\mathbb EX_{ij}\right)\\
&=1+\frac1{nm}\sum_{i=1}^n(n-i)\\
&=1+\frac1{nm}\left(n^2-\frac{n(n+1)}2\right)\\
&=1+\frac{n-1}{2m}=1+\frac\alpha2-\frac\alpha{2n}.
\end{aligned}$$
Использованы линейность ожидания и $\mathbb EX_{ij}=\Pr(X_{ij}=1)=1/m$. С учётом постоянной подготовки поиска получаем заявленную оценку. Если цепочки строятся иначе, конкретная формула числа сравнений требует проверки порядка. Линейность ожидания сама по себе не требует независимости индикаторов.

При ограниченном $\alpha$ обе оценки становятся $\Theta(1)$ **в ожидании**. Если все ключи попали в одну цепочку, отдельная операция занимает $\Theta(n)$.

## Открытая адресация и последовательность проб

Вместо отдельных списков записи хранятся непосредственно в ячейках массива. При коллизии проверяется последовательность
$$h(k,0),h(k,1),\ldots,h(k,m-1).$$
Она должна позволять добраться до подходящих ячеек; вставка и поиск используют одинаковое правило проб.

![[Хеширование — открытая адресация.png]]

Стрелки показывают продолжение поиска после занятой исходной ячейки. Запись остаётся в массиве, а не уходит в отдельный список.

| Метод | Формула |
|---|---|
| Линейное пробирование | $h(k,i)=(h'(k)+i)\bmod m$ |
| Квадратичное | $h(k,i)=(h'(k)+c_1i+c_2i^2)\bmod m$ |
| Двойное хеширование | $h(k,i)=(h_1(k)+ih_2(k))\bmod m$ |

![[Хеширование — квадратичное и двойное пробирование.png]]

В исходной иллюстрации одинаковые начальные позиции разводятся дополнительными пробами: слева показаны квадратичные смещения, справа — шаг второй хеш-функции. Обозначения $i+1$, $i+4$ относятся к квадратам номеров проб.

**Дополнительное условие корректности:** линейная последовательность обходит все ячейки; квадратичная при произвольных параметрах этого не гарантирует. Для двойного хеширования полный обход получается при взаимной простоте шага $h_2(k)$ и $m$. Нельзя считать «не найдено» доказанным после повторения одного малого набора ячеек.

## Неуспешный поиск при открытой адресации

**Теорема из лекции 8.** Если $n<m$, $\alpha=n/m<1$, нет удалённых меток и действует равномерная модель пробирования — последовательность проб каждого ключа является равновероятной перестановкой ячеек, — ожидаемое число проб неуспешного поиска не превосходит
$$\frac1{1-\alpha}.$$
Это более сильная модель, чем равномерность только первой корзины. Не следует автоматически переносить её на линейное или произвольное квадратичное пробирование.

**Полное доказательство по слайдам.** Пусть $X$ — число проб до первой пустой ячейки. Событие $X\ge i$ означает, что первые $i-1$ проб попали в занятые ячейки. После $j$ занятых проб остаются $n-j$ занятых среди $m-j$ ещё не проверенных:
$$\Pr(X\ge i)=\frac nm\frac{n-1}{m-1}\cdots\frac{n-i+2}{m-i+2}.$$
При выходе за возможное число занятых ячеек вероятность равна нулю. Поскольку $n<m$,
$$\frac{n-j}{m-j}\le\frac nm=\alpha,$$
и потому $\Pr(X\ge i)\le\alpha^{i-1}$. Для положительной целочисленной случайной величины
$$\mathbb EX=\sum_{i\ge1}\Pr(X\ge i)
\le\sum_{i\ge1}\alpha^{i-1}
=\sum_{r\ge0}\alpha^r=\frac1{1-\alpha}.$$
**Промежуточное пояснение:** тождество для ожидания следует из $X=\sum_{i\ge1}\mathbf1_{\{X\ge i\}}$. Первая проба происходит всегда, вторая нужна примерно с вероятностью $\alpha$, третья — не больше $\alpha^2$ и так далее. При заполнении наполовину граница равна $2$, при заполнении на $90\%$ — $10$. Рост заполнения ухудшает поиск ещё до полного исчерпания мест.

## Рехеширование

При изменении размера $m$ меняется индекс, поэтому нельзя просто дописать пустые ячейки в конец старого массива. Создают новое хранилище и заново размещают **все живые записи** по ключам и новой вместимости. Удалённые метки не переносятся.

![[Рехеширование — перераспределение.png]]

Стрелки показывают смену корзин; старые соседи могут разойтись, а новые — встретиться. На слайде также записана составная функция $(h(k)\bmod A)\bmod m$: менять нужно фактически используемое правило. Пересборка с обнулением нового массива стоит $O(n+m_{new})$ при подходящем хешировании; при геометрическом росте и ограниченном заполнении — ожидаемо $O(n)$.

**Дополнительное пояснение:** ожидаемая стоимость поиска связана с распределением хешей; амортизированная стоимость вставки с ростом — с распределением работы пересборок по последовательности операций. Это разные основания оценки. Вставка, вызвавшая пересборку, не обязана стоить $O(1)$.

## Универсальное хеширование

Семейство $\mathcal H$ универсально, если для любых разных фиксированных ключей $k\ne l$ число функций с $h(k)=h(l)$ не превосходит $|\mathcal H|/m$. При равномерном случайном выборе $h\in\mathcal H$:
$$\Pr_h\{h(k)=h(l)\}\le\frac1m.$$
Рандомизируется выбор функции, что уменьшает зависимость от заранее фиксированного набора ключей.

Пример семейства из лекции:
$$h_{ab}(k)=((ak+b)\bmod p)\bmod m,$$
$$a\in\{1,\ldots,p-1\},\quad b\in\{0,\ldots,p-1\},\quad p>m.$$
**Уточнение условий:** $p$ — простое, ключи — различные элементы $\mathbb Z_p$; нельзя без дополнительного кодирования сворачивать разные ключи в один остаток по $p$. Число пар параметров $p(p-1)$. В презентации указана ссылка на теорему Кормена, но самого доказательства универсальности нет.

**Уточнение фразы слайда «для insert выбирается случайная функция»:** функцию выбирают для таблицы, сохраняют её параметры и используют для вставки, поиска и удаления. Смена функции требует рехеширования. Независимый новый выбор для каждого `insert` без сохранения информации о размещении нарушил бы поиск.

## Идеальное хеширование

Для заранее фиксированного набора ключей строится двухуровневая таблица: первая функция распределяет ключи по корзинам, а для корзины с $n_j$ ключами создаётся отдельная таблица размера $n_j^2$ и подбирается функция без коллизий. Поиск делает два вычисления индекса и проверку ключа, то есть занимает $O(1)$ в худшем случае в построенной статической структуре.

![[Идеальное хеширование — два уровня.png]]

Слева — первый уровень, справа — таблицы разного размера с разными параметрами функций. Большая корзина получает квадратично больше мест для устранения коллизий. Лекция утверждает: при подходящем выборе первого уровня суммарная память $O(n)$; полного доказательства построения нет. Это не обещание отсутствия коллизий у любой обычной таблицы.
