# Память, указатели и представление данных

> [!abstract] Суть
> Данные занимают память, а тип задаёт способ их интерпретации. Указатель хранит адрес, но сам по себе не гарантирует, что по этому адресу существует подходящий живой объект.

## Значение, адрес и тип

### Какие представления сравнивает лекция

Обзорная схема лекции 5 перечисляет простые значения (целые, вещественные, символы, строки), коллекции (массивы, хеш-таблицы, кортежи, структуры) и динамические структуры (связные списки, очереди, стеки, графы, деревья). Это учебная группировка, а не строгая классификация типов C: строка в C представляется массивом символов, а очередь и стек определяют порядок операций и могут иметь разные реализации. Графы, деревья, хеш-таблицы и кортежи в этой презентации только названы, их устройство здесь не раскрывается.

Массив объединяет однотипные элементы, структура — поля разных типов, связный список — узлы через ссылки, указатель хранит адрес другого объекта. Хотя вводный слайд противопоставляет C++ и Python, основные примеры записаны на C: результаты вроде `sizeof('a')` ниже относятся именно к C.

### Значение и адрес объекта

У объекта есть значение, адрес и время жизни. Оператор `&` получает адрес, а разыменование `*` обращается к объекту через указатель. Разыменование допустимо лишь при корректном адресе, подходящем типе и продолжающемся времени жизни объекта.

Размер типа измеряется оператором `sizeof`. Конкретные размеры `int`, указателей и структур зависят от реализации и платформы. `sizeof(char)` всегда равен одному байту C; число битов в таком байте задаёт `CHAR_BIT`. Поэтому числа размеров из лекционных примеров нельзя считать универсальными.

В структуру могут добавляться промежутки для выравнивания полей. Её размер не обязан равняться сумме размеров полей. Выравнивание согласует расположение объектов с требованиями платформы.

## Массивы и строки

Элементы массива расположены последовательно. Для указателя `p` на элемент типа `T` выражение `p + i` смещается на `i` элементов, а не на `i` байтов. Допустимая арифметика указателей ограничена соответствующим массивом и позицией сразу за ним; последнюю нельзя разыменовывать.

Массив и указатель — разные сущности, хотя во многих выражениях имя массива преобразуется в указатель на первый элемент. В частности, `sizeof` самого массива даёт размер всего массива, а `sizeof` указателя — размер адресного значения.

Строка C заканчивается нулевым символом `\0`. Длина текста не включает этот символ, но память под строку должна его вмещать. Литерал `"a"` содержит два символа, а символьная константа `'a'` в C имеет тип `int`.

## Динамическая память и владение

`malloc` выделяет область с неопределённым начальным содержимым, `calloc` дополнительно обнуляет её байты. Успех выделения необходимо отличать от отказа. `free` завершает существование выделенной области; старые указатели не становятся автоматически нулевыми и не дают права продолжать доступ.

`realloc` может перенести область в другое место. При успешном переносе старые адреса теряют актуальность. При отказе для ненулевого запрошенного размера исходный блок остаётся выделенным. Поэтому потеря единственного сохранённого адреса исходного блока приводит к утечке.

Владение — соглашение о том, кто отвечает за освобождение ресурса. Копия адреса не создаёт новый объект и не делает безопасным повторное освобождение.

## Обобщённое хранение

`void*` позволяет передавать адрес объекта без фиксации его конкретного типа. Но для чтения требуется знать представление данных, а для вычисления смещения — размер элемента. В стандартном C арифметика непосредственно над `void*` не определена.

Обобщённый массив хранит адрес буфера и размер элемента отдельно. Копирование байтов структуры с указателем копирует сам указатель, а не объект за ним. При копировании адреса объект за ним остаётся общим; независимая копия требует отдельного решения о копировании данных.

## Длительность хранения и корректность доступа

В PDF используются три практических области: стек для автоматических локальных объектов, куча для `malloc`, статическая область для глобальных объектов и строковых литералов. Это модель распространённых реализаций; стандарт C задаёт длительность хранения, а не обязательные названия физических областей. Утверждение «в C всей памятью занимается программист» относится прежде всего к динамическим ресурсам: автоматические и статические объекты язык также обслуживает по своим правилам.

Модель памяти — адресуемые байты. В распространённом восьмибитном байте $2^8=256$ комбинаций: беззнаковое значение 0–255, при обычном знаковом представлении −128–127. Стандартный байт C имеет `CHAR_BIT` бит, не обязательно 8. `char` хранит единицу представления; это не обещание вместить любой символ Unicode.

Ошибка выхода за границы, обращения к уже освобождённому объекту или изменения строкового литерала приводит к неопределённому поведению, а не к одному гарантированному исходу. Иллюстрации PDF — повреждение соседних данных, отсутствие видимого эффекта, аварийное завершение — возможны, но не исчерпывают последствия. Компилятор может диагностировать часть ошибок, однако общей автоматической проверки границ C не требует.

## Размеры и диапазоны из лекции

Таблица — пример распространённой 64-битной среды с восьмибитными байтами, `int` 32 бита, моделью LP64 и IEEE 754. Реальные значения проверяются средствами реализации.

| Тип | Размер в примере, байт | Диапазон или точность |
|---|---|---|
| `bool` | 1 | Ложь и истина |
| `char` при знаковом варианте | 1 | −128…127; обычный `char` может быть и беззнаковым |
| `unsigned char` | 1 | 0…255 |
| `short int` / `unsigned short` | 2 | −32768…32767 / 0…65535 |
| `int` / `unsigned int` | 4 | −2147483648…2147483647 / 0…4294967295 |
| `long int`, `long long` | 8 | Около $\pm9{,}2\cdot10^{18}$ для знакового 64-битного |
| `unsigned long int` в LP64 | 8 | $0\ldots2^{64}-1$ |
| `float` | 4 | Обычно около 6–7 значащих десятичных цифр |
| `double` | 8 | Обычно 15–16 значащих десятичных цифр |
| `long double` | В исходной таблице 16 | Может иметь другие размер и точность, в том числе на 64-битной системе |
| Указатель на объект | В примере 8 | Размер зависит от платформы и типа указателя |

`int8_t`, `uint8_t` и другие точные типы из `<stdint.h>` имеют указанную разрядность, если соответствующий тип поддерживается. Префикс `u` означает беззнаковость. `size_t` — беззнаковый тип размеров, результат `sizeof`; длину динамического массива хранят отдельно.

Для восьмибитного беззнакового значения $2^8=256$ вариантов дают диапазон $0\ldots255$, для показанного знакового — $-128\ldots127$. В 64-битном примере соответствующие диапазоны — $0\ldots2^{64}-1$ и $-2^{63}\ldots2^{63}-1$. Один и тот же размер хранения не делает знаковый и беззнаковый диапазоны одинаковыми.

В примере базы шахматных партий выбор более узких подходящих типов уменьшил размер с 7,21 до 3,90 ГБ. Это результат конкретных данных, а не универсальный коэффициент. Аналогично упомянутый в PDF пятикратный расход памяти списка целых Python относительно массива C зависит от представления и реализации. Наличие внутреннего цикла в `setobject.c` не означает, что поиск в хеш-множестве обязан быть линейным по всем элементам.

## sizeof: выражение, объект и массив

| Выражение | Результат в описанном примере |
|---|---|
| `sizeof(true)` в C11/C17 с `<stdbool.h>` | `sizeof(int)`, обычно 4: макрос заменяется целочисленной константой 1 |
| `sizeof(false)` в том же режиме | `sizeof(int)`, обычно 4 |
| `sizeof(_Bool)` | Обычно 1; это булев тип C11/C17 |
| `sizeof(bool)` и `sizeof` объекта `bool` | Обычно 1 |
| `sizeof` настоящего `bool arr[10]` | `10 * sizeof(bool)` |
| `sizeof` указателя на выделенные 10 элементов | Размер указателя, обычно 8 |
| `sizeof(1)`, `sizeof(2147483647)` | Обычно 4 |
| `sizeof(2147483648)` | В LP64 обычно 8: константа не помещается в `int`, выбирается следующий подходящий тип |
| `sizeof` массива `int arr[10]` | `10 * sizeof(int)`, обычно 40 |
| `sizeof('a')` | `sizeof(int)` для обычной символьной константы C |
| `sizeof(L'ы')` | `sizeof(wchar_t)`, в среде слайда 4; это широкая символьная константа, её размер зависит от реализации |
| `sizeof` объекта `char` | 1 |
| `sizeof("a")` | 2: символ и `\0` |
| `sizeof("ы")` в UTF-8 | 3 |
| `sizeof` массива `char str[]="hello"` | 6 |
| `sizeof("Привет")` в UTF-8 | 13 |

В C23 `true` имеет тип `bool`, поэтому прежний результат для `sizeof(true)` не переносится автоматически. Строковые размеры зависят от кодировки исполнения; UTF-8 использует от 1 до 4 байтов на кодовую точку. Для показанной кириллицы — 2. `strlen("Привет")` в UTF-8 равно 12, а не числу букв 6.

Для печати результата `sizeof` используют `%zu`, потому что его тип — `size_t`: например, `printf("%zu\n", sizeof(bool));`. Показанное в слайдах `%ld` не является переносимым форматом для этого типа. Различие `'a'`, `L'ы'` и строковых литералов — различие типов выражений, а не только длины текста. Уточнения: [проект C11 N1570](https://www.open-std.org/jtc1/sc22/wg14/www/docs/n1570.pdf), разделы «Character constants» и «The fprintf function».

Сравнение с объектами Python, включая отсутствующий в текстовом слое слайдов код и графики размеров, разобрано в [[Представление объектов и расход памяти в C и Python]].

## Представление вещественных чисел

В обычных форматах IEEE 754 `float` binary32 содержит знак (1 бит), поле экспоненты (8) и дробную часть (23); `double` binary64 — 1, 11 и 52. Нормализованная значащая часть включает неявную единицу. Пример 100: $(1+0{,}5625)2^6=100$.

Для нормализованного binary32 используется формула $(-1)^s(1+f)2^{E-127}$. В примере 100 поля равны $s=0$, $E=133$, $f=0.100100_2=0{,}5625$. Для 1010,1097 на слайде $E=136$, так что степень равна $136-127=9$; двоичная дробная часть округляется при сохранении.

Приведённые на слайдах порядки $10^{-38}\ldots10^{38}$ и $10^{-308}\ldots10^{308}$ описывают масштабы нормализованных положительных чисел, а не все представимые значения. Есть ноль, отрицательные значения и субнормальные числа меньшего модуля. Наибольшие конечные модули в показанных форматах — приблизительно $3{,}4028235\cdot10^{38}$ и $1{,}797693\cdot10^{308}$. Для `long double` в таблице слайда указаны 16 байт и максимум порядка $1{,}1897314\cdot10^{4932}$; это характеристика конкретного представления, не обязательный формат C, и размер хранения 16 байт сам по себе не доказывает 128 бит значащего формата.

Число 1010,1097 при сохранении в типичном `float` оказывается приблизительно 1010,109680. Конечное число двоичных разрядов не представляет каждую десятичную дробь точно, как конечная десятичная запись не представляет $1/3$.

Равенство вещественных чисел через `==` допустимо, но при ожидаемых погрешностях вычислений оно может не выражать нужный критерий. Пример источника `fabs(a-b)<0.000001` задаёт абсолютный допуск для конкретного масштаба. Его нельзя объявлять подходящим для любых значений. Ошибка калькулятора с результатом 1 073 676 289 — пример потери точности `float`.

## Указатели: значение, сдвиги и адреса

```c
#include <stdio.h>

void pointer_demo(void) {
    int x = 5;
    int *p = &x;
    printf("%d\n", *p);
    *p = 10;
    printf("%p %d\n", (void *)p, x);
}
```

`%p` получает указатель, приведённый к `void *`. Для `short *` сдвиг на 1 в примере означает 2 байта, для `int *` — 4, для `double *` — 8; общее правило — `sizeof` соответствующего элемента. `arr[i]` равносильно `*(arr+i)`.

В PDF локальные `short val1` и `val2` оказались по адресам `…e06` и `…e04`. Это наблюдение конкретной сборки: расположение отдельных локальных объектов и направление стека не гарантируют соседство. Выражение `&val1 - 1` нельзя использовать как корректный способ попасть в отдельную `val2`: арифметика разрешена в рамках одного массива.

Для двух элементов одного выделенного массива корректный пример:

```c
#include <stdio.h>
#include <stdlib.h>

void short_array_demo(void) {
    short *arr = malloc(2 * sizeof *arr);
    if (arr == NULL) return;
    arr[0] = 1;
    arr[1] = 2;
    printf("%p %p\n", (void *)arr, (void *)(arr + 1));
    printf("%d %d\n", arr[0], arr[1]);
    free(arr);
}
```

Элементы массива идут по возрастанию адресов и в куче, и в автоматическом массиве. Исходное чтение неинициализированных `short` заменено записью значений до чтения. Два восьмибитных байта `1, 2` при little-endian представлении 16-битного беззнакового значения дают $2\cdot256+1=513$; порядок байтов тоже является условием примера.

Полная схема динамического массива на слайде показывает четыре последовательных байта `1, 2, 3, 4`. При тех же условиях первый 16-битный элемент равен $1+2\cdot256=513$, второй — $3+4\cdot256=1027$. Между началами элементов два байта: например, `…6070` и `…6072`. Эти значения иллюстрируют заданные байты схемы; сам `malloc` их не записывает и не обещает нулей, несмотря на комментарии исходного кода.

## Раскладка структур и выравнивание

```c
struct A { int x; };
struct B { char c; int x; };
struct C { int x; char c; };
struct D { char c; double d; };
```

При типичных выравниваниях 4 для `int` и 8 для `double` размеры — 4, 8, 8 и 16. Раскладки:

```text
B: [c][_][_][_][x][x][x][x]
C: [x][x][x][x][c][_][_][_]
D: [c][_][_][_][_][_][_][_][d][d][d][d][d][d][d][d]
```

Промежутки соблюдают выравнивание полей; хвостовые промежутки обеспечивают правильное начало следующего элемента массива структур. Порядок полей может влиять на размер. Совет «от больших к меньшим» — эвристика, ориентироваться нужно на выравнивания и требования платформы, а не только размер.

## Выделение, изменение размера и владение

```c
#include <stdlib.h>

void allocation_demo(void) {
    int *arr = malloc(5 * sizeof *arr);
    int *zero_list = calloc(5, sizeof *zero_list);
    if (arr == NULL || zero_list == NULL) {
        free(arr);
        free(zero_list);
        return;
    }
    arr[0] = 7;
    arr[4] = 9;
    int *tmp = realloc(arr, 10 * sizeof *arr);
    if (tmp == NULL) {
        free(arr);
        free(zero_list);
        return;
    }
    arr = tmp;
    free(arr);
    free(zero_list);
}
```

У `malloc` неинициализированное содержимое; `calloc` обнуляет байты (это не универсальное обещание нулевого представления любого возможного типа). При ненулевом размере неудачный `realloc` оставляет старую область живой. Присваивание `arr=realloc(arr,...)` сразу теряет её адрес при отказе; `free(NULL)` не возвращает потерянную память. Временный указатель сохраняет возможность корректной очистки или восстановления.

Успешно выделенную область освобождают один раз, когда она больше не нужна. Повторное `free` — неопределённое поведение, не обязательно гарантированное падение. Утечка возникает и без потери адреса, если ресурс больше не нужен, но его не освобождают. При успешном `realloc` старые указатели на элементы больше нельзя считать действительными.

Нужно различать `*arr_size++` (разбирается как `*(arr_size++)`, увеличивает указатель) и `(*arr_size)++` (увеличивает значение по адресу).

Проверка уточнений стандартов: [WG14 — проекты стандартов C](https://www9.open-std.org/JTC1/SC22/WG14/www/projects.html), [GCC — булев тип и C23](https://gcc.gnu.org/onlinedocs/gcc-15.2.0/gcc/Boolean-Type.html).
