### Сборка, функции и управление потоком

- **Сборка C:** препроцессинг → компиляция → ассемблирование → компоновка. Заголовок объявляет интерфейс, исходный файл содержит реализацию; статическая библиотека передаёт объектный код при сборке, динамическая загружается отдельно. `make` пересобирает цели по зависимостям и времени изменения файлов.
- **Вызов:** аргументы передаются по значению; указатель тоже копируется, но через него можно изменить доступный живой объект. Область видимости имени и время жизни объекта — разные свойства.
- **Управление:** ноль и нулевой указатель ложны, остальные скалярные значения истинны; `&&` и `||` вычисляются с коротким замыканием. `switch` продолжает выполнение после метки до `break`/`return`; `for` и `while` проверяют условие до тела, `do…while` — после первого выполнения.

Подробно: [[От исходного текста к работающей программе]], [[Функции, переменные и управление потоком в C]].

### Память, указатели, строки и представление

- **Адресация:** `p + i` сдвигает указатель на $i\cdot\mathrm{sizeof}(T)$ байтов C для `T *p`; арифметика ограничена массивом и позицией сразу после него, которую нельзя разыменовывать. Для настоящего массива число элементов — `sizeof a / sizeof a[0]`; из указателя длина не восстанавливается.
- **Владение:** `malloc` выделяет память, `calloc` обнуляет байты, `free` освобождает. `realloc` может сменить адрес; при отказе для ненулевого нового размера старый блок сохраняется, поэтому результат сначала записывают во временный указатель. После освобождения или успешного переноса старые адреса непригодны.
- **Обобщение:** `void *` переносит адрес; для чтения нужны правильный тип и живой объект. Смещение обобщённого элемента: `(char *)data + i * elem_size`; побайтовая копия не создаёт независимые копии объектов по вложенным указателям.
- **Строки:** строка завершается `\0`; `strlen` не считает терминатор, `sizeof "Hello"` равен $6$. Литерал менять нельзя, массив `char s[]="Hello"` изменяем. `strcmp(a,b)==0` означает равенство содержимого; `strcpy`/`strcat` требуют достаточного буфера, `memcpy` — неперекрывающихся областей, при перекрытии нужен `memmove`.
- **Размеры:** `sizeof` учитывает размер объекта и выравнивание структуры; размеры типов зависят от реализации. `sys.getsizeof` в Python измеряет сам объект без рекурсивного обхода ссылок; `list` CPython хранит ссылки, массив C — значения. Числа размеров из слайдов относятся к конкретной среде.
- **Вещественные числа:** для нормализованного binary32 значение $(-1)^s(1+f)2^{E-127}$, поля — $1+8+23$ бита; binary64 — $1+11+52$. Конечная точность представления требует учитывать округление.

Подробно: [[Память, указатели и представление данных]], [[Строки, библиотеки и разделение программы на файлы]], [[Представление объектов и расход памяти в C и Python]].

### Контейнеры и стоимость операций

- **Динамический массив:** $0\le size\le capacity$; индексирование $O(1)$, поиск и вставка/удаление со сдвигом $O(n)$. При геометрическом росте вместимости добавление в конец имеет амортизированную стоимость $O(1)$, отдельное расширение — $O(n)$. Рост на одно место может дать $O(n^2)$ переносов для $n$ добавлений.
- **Список:** индексирование и поиск $O(n)$; вставка/удаление по уже известным нужным связям — $O(1)$. Для односвязного списка важен известный предшественник; для добавления в конец за $O(1)$ нужен сохранённый хвост. В показанном списке только с `head` добавление в конец требует обхода.
- **Vector:** хранит `data`, `size`, `capacity`, обобщённый вариант — ещё `elem_size`. Добавление сначала обеспечивает вместимость, затем копирует значение и увеличивает размер; удаление копирует результат, сдвигает хвост и уменьшает размер. Возвращаемой выделенной копией владеет вызывающий код. Отсутствующая в источнике реализация `resize` остаётся контрактом.
- **Обобщённый список:** узел содержит данные и `next`; сравнение передаётся через указатель на функцию `EqualsFunc`. Поиск обходит узлы и возвращает найденную позицию либо отдельный признак отсутствия. При стоимости сравнения $O(1)$ поиск стоит $O(n)$.
- **Память и скрытые обходы:** буфер массива занимает $capacity\cdot elem\_size$ плюс управление; у списка есть узлы, указатели, данные и расходы аллокатора. Повторный `array.count(v)` для каждого из $k$ различных значений требует $O(nk)$ работы; короткая запись не устраняет обходы.

Подробно: [[Динамический массив, список и стоимость операций]], [[Vector — устройство и операции]], [[Обобщённый связный список и функции сравнения]].

### Чтение, скользящее среднее и корректность

- **Чтение чисел:** открыть файл → читать символы в `int` до `EOF` → накапливать токен → преобразовать и добавить при разделителе → обработать последний токен → закрыть файл. Проверяются переполнение буфера, диапазон числа, отказ выделения и ошибки файла.
- **Скользящее среднее:** при $1\le w\le n$ полных окон $n-w+1$, $y_i=\frac1w\sum_{j=0}^{w-1}x_{i+j}$. Пересчёт каждого окна — $O(nw)$; сохранение суммы $S_{i+1}=S_i-x_i+x_{i+w}$ даёт $O(n)$ при постоянном доступе к входящему и уходящему элементам. Промежуточная сумма должна помещаться в выбранный тип.
- **Подсчёт делителей:** полный перебор для $n>0$ — $O(n)$; перебор пар $d,n/d$ до $\sqrt n$ — $O(\sqrt n)$, квадратный корень учитывается один раз. Условие `d <= n / d` позволяет избежать переполнения `d*d`.
- **Проверка корректности:** контракт задаёт допустимые входы, результат и владение ресурсами; инвариант связывает шаги алгоритма. Границы типов, нули, пустые данные и ошибки ресурсов требуют отдельных случаев. `assert` может отключаться через `NDEBUG`; успешные тесты не являются доказательством для всех входов.
- **Измерение:** процессорное время через `clock` переводится в секунды как `(finish-start)/CLOCKS_PER_SEC`; асимптотика описывает рост затрат, а не конкретное время выполнения.

Подробно: [[Чтение чисел из файла и скользящее среднее]], [[Тестирование и корректность программ на C]].
