### Сборка, функции и управление потоком

- **Сборка C:** препроцессинг → компиляция → ассемблирование → компоновка. Заголовок объявляет интерфейс, исходный файл содержит реализацию; статическая библиотека передаёт объектный код при сборке, динамическая загружается отдельно. `make` пересобирает цели по зависимостям и времени изменения файлов.
- **Вызов:** аргументы передаются по значению; указатель тоже копируется, но через него можно изменить доступный живой объект. Область видимости имени и время жизни объекта — разные свойства.
- **Управление:** ноль и нулевой указатель ложны, остальные скалярные значения истинны; `&&` и `||` вычисляются с коротким замыканием. `switch` продолжает выполнение после метки до `break`/`return`; `for` и `while` проверяют условие до тела, `do…while` — после первого выполнения.

Подробно: [[От исходного текста к работающей программе]], [[Функции, переменные и управление потоком в C]].

### Память, указатели, строки и представление

- **Адресация:** `p + i` сдвигает указатель на $i\cdot\mathrm{sizeof}(T)$ байтов C для `T *p`; арифметика ограничена массивом и позицией сразу после него, которую нельзя разыменовывать. Для настоящего массива число элементов — `sizeof a / sizeof a[0]`; из указателя длина не восстанавливается.
- **Владение:** `malloc` выделяет память, `calloc` обнуляет байты, `free` освобождает. `realloc` может сменить адрес; при отказе для ненулевого нового размера старый блок сохраняется, поэтому результат сначала записывают во временный указатель. После освобождения или успешного переноса старые адреса непригодны.
- **Обобщение:** `void *` переносит адрес; для чтения нужны правильный тип и живой объект. Смещение обобщённого элемента: `(char *)data + i * elem_size`; побайтовая копия не создаёт независимые копии объектов по вложенным указателям.
- **Строки:** строка завершается `\0`; `strlen` не считает терминатор, `sizeof "Hello"` равен $6$. Литерал менять нельзя, массив `char s[]="Hello"` изменяем. `strcmp(a,b)==0` означает равенство содержимого; `strcpy`/`strcat` требуют достаточного буфера, `memcpy` — неперекрывающихся областей, при перекрытии нужен `memmove`.
- **Размеры:** `sizeof` учитывает размер объекта и выравнивание структуры; размеры типов зависят от реализации. `sys.getsizeof` в Python измеряет сам объект без рекурсивного обхода ссылок; `list` CPython хранит ссылки, массив C — значения. Числа размеров из слайдов относятся к конкретной среде.
- **Вещественные числа:** для нормализованного binary32 значение $(-1)^s(1+f)2^{E-127}$, поля — $1+8+23$ бита; binary64 — $1+11+52$. Конечная точность представления требует учитывать округление.

Подробно: [[Память, указатели и представление данных]], [[Строки, библиотеки и разделение программы на файлы]], [[Представление объектов и расход памяти в C и Python]].

### Контейнеры и стоимость операций

- **Динамический массив:** $0\le size\le capacity$; индексирование $O(1)$, поиск и вставка/удаление со сдвигом $O(n)$. При геометрическом росте вместимости добавление в конец имеет амортизированную стоимость $O(1)$, отдельное расширение — $O(n)$. Рост на одно место может дать $O(n^2)$ переносов для $n$ добавлений.
- **Список:** индексирование и поиск $O(n)$; вставка/удаление по уже известным нужным связям — $O(1)$. Для односвязного списка важен известный предшественник; для добавления в конец за $O(1)$ нужен сохранённый хвост. В показанном списке только с `head` добавление в конец требует обхода.
- **Vector:** хранит `data`, `size`, `capacity`, обобщённый вариант — ещё `elem_size`. Добавление сначала обеспечивает вместимость, затем копирует значение и увеличивает размер; удаление копирует результат, сдвигает хвост и уменьшает размер. Возвращаемой выделенной копией владеет вызывающий код. Отсутствующая в источнике реализация `resize` остаётся контрактом.
- **Обобщённый список:** узел содержит данные и `next`; сравнение передаётся через указатель на функцию `EqualsFunc`. Поиск обходит узлы и возвращает найденную позицию либо отдельный признак отсутствия. При стоимости сравнения $O(1)$ поиск стоит $O(n)$.
- **Память и скрытые обходы:** буфер массива занимает $capacity\cdot elem\_size$ плюс управление; у списка есть узлы, указатели, данные и расходы аллокатора. Повторный `array.count(v)` для каждого из $k$ различных значений требует $O(nk)$ работы; короткая запись не устраняет обходы.

Подробно: [[Динамический массив, список и стоимость операций]], [[Vector — устройство и операции]], [[Обобщённый связный список и функции сравнения]].

### Чтение, скользящее среднее и корректность

- **Чтение чисел:** открыть файл → читать символы в `int` до `EOF` → накапливать токен → преобразовать и добавить при разделителе → обработать последний токен → закрыть файл. Проверяются переполнение буфера, диапазон числа, отказ выделения и ошибки файла.
- **Скользящее среднее:** при $1\le w\le n$ полных окон $n-w+1$, $y_i=\frac1w\sum_{j=0}^{w-1}x_{i+j}$. Пересчёт каждого окна — $O(nw)$; сохранение суммы $S_{i+1}=S_i-x_i+x_{i+w}$ даёт $O(n)$ при постоянном доступе к входящему и уходящему элементам. Промежуточная сумма должна помещаться в выбранный тип.
- **Подсчёт делителей:** полный перебор для $n>0$ — $O(n)$; перебор пар $d,n/d$ до $\sqrt n$ — $O(\sqrt n)$, квадратный корень учитывается один раз. Условие `d <= n / d` позволяет избежать переполнения `d*d`.
- **Проверка корректности:** контракт задаёт допустимые входы, результат и владение ресурсами; инвариант связывает шаги алгоритма. Границы типов, нули, пустые данные и ошибки ресурсов требуют отдельных случаев. `assert` может отключаться через `NDEBUG`; успешные тесты не являются доказательством для всех входов.
- **Измерение:** процессорное время через `clock` переводится в секунды как `(finish-start)/CLOCKS_PER_SEC`; асимптотика описывает рост затрат, а не конкретное время выполнения.

Подробно: [[Чтение чисел из файла и скользящее среднее]], [[Тестирование и корректность программ на C]].

### Хеш-таблицы и представление словаря

- **Прямая адресация:** для универсума $\{0,\ldots,m-1\}$ поиск/вставка/удаление обращаются к `T[k]` за $O(1)$, память $\Theta(m)$. Для частот неотрицательных ключей с максимумом $M$ нужны $M+1$ ячеек; полный подсчёт $\Theta(n+M+1)$.
- **Хеширование:** $h:U\to\{0,\ldots,m-1\}$; коллизия — $h(k)=h(l)$ при $k\ne l$. Деление: $h(k)=k\bmod m$. Умножение: $h(k)=\lfloor m\{kA\}\rfloor$, $0<A<1$, в лекции $A\approx(\sqrt5-1)/2$. Индекс должен быть неотрицательным; равенство ключей проверяется отдельно от хеша.
- **Цепочки:** $\alpha=n/m$ — средняя длина цепочки. При простом равномерном хешировании и константной стоимости хеша/сравнения ожидаемое время поиска $\Theta(1+\alpha)$. Для неуспеха ожидаемая длина цепочки $\alpha$; при равновероятном успешном запросе и вставке в голову число проверок в ожидании $1+(n-1)/(2m)$. Худшая операция может быть линейной.
- **Пробы открытой адресации:** линейные $(h'(k)+i)\bmod m$, квадратичные $(h'(k)+c_1i+c_2i^2)\bmod m$, двойной хеш $(h_1(k)+ih_2(k))\bmod m$. Полнота обхода требует условий на параметры; для двойного хеша шаг взаимно прост с $m$.
- **Граница поиска:** при $\alpha<1$, без удалённых меток и равномерном выборе перестановки проб ожидаемое число проб неуспеха не больше $1/(1-\alpha)$. Это не автоматическая гарантия конкретного линейного/квадратичного правила.
- **Состояния и пересборка:** `EMPTY`, `OCCUPIED`, `DELETED`; поиск проходит через удалённые места. После изменения вместимости заново размещаются все живые пары. Геометрический рост даёт ожидаемо амортизированные постоянные вставки при контроле заполнения, но отдельная пересборка линейна по числу записей и новому массиву.
- **Универсальное семейство:** для разных фиксированных ключей $\Pr_h(h(k)=h(l))\le1/m$. Пример $h_{ab}(k)=((ak+b)\bmod p)\bmod m$, простое $p>m$, ключи в $\mathbb Z_p$, $1\le a<p$, $0\le b<p$; параметров $p(p-1)$. Функция фиксируется для таблицы до рехеширования. Идеальное статическое хеширование использует второй уровень размера $n_j^2$ в корзине и при подходящем построении даёт $O(n)$ памяти и худший поиск $O(1)$ при постоянной стоимости ключевых операций.
- **Пара в C:** два указателя `GenericPair`, упакованные `key_size+val_size` байтов либо указатель на отдельный блок — разные представления. `sizeof(key_size+val_size)` не равен сумме размеров. Ключ и значение, теги состояний, выравнивание и владение учитываются отдельно; `const void *` не запрещает переназначение самого указателя.

Подробно: [[Хеш-таблицы — функции, коллизии и оценки]], [[Реализация хеш-таблиц на C]].

### Асимптотические границы и бинарный поиск

- **Границы роста:** для в итоге неотрицательных $f,g$, $g>0$, $f\in O(g)$ означает $f\le Cg$ при достаточно больших аргументах; $\Omega(g)$ — $f\ge cg$; $\Theta(g)$ — обе границы. $f=o(g)$: для каждого $\varepsilon>0$ в итоге $f\le\varepsilon g$; $f=\omega(g)$: для каждого $C>0$ в итоге $f\ge Cg$. Это виды границ, а не названия лучшего, худшего и среднего случаев.
- **Рост:** $3n+7\in\Theta(n)$, $n=o(n^2)$, $\log n=o(n)$, $\log n=\omega(1)$. Постоянные множители не меняют класс. Временная и дополнительная пространственная сложности оцениваются отдельно; ожидание требует вероятностной модели, амортизация — последовательности операций.
- **Повторения:** поиск очередного ключа в массиве `seen` даёт в худшем случае $\Theta(n^2)$; множество с ожидаемо постоянными операциями — $\Theta(n)$ ожидаемого времени и $O(n)$ памяти, сохраняя первые вхождения. Нахождение повторений и удаление всех значений с частотой больше одного — разные операции.
- **Бинарный поиск:** упорядоченный массив, постоянные индексирование и сравнение, трёхзначный компаратор. Диапазон уменьшается примерно вдвое; худшее время $\Theta(\log n)$ при $n\ge2$, лучшее непустое $\Theta(1)$, итеративная дополнительная память $\Theta(1)$. Полуинтервал `[low,high)` позволяет безопасно обработать пустой вход.

Подробно: [[Асимптотика — рост времени и памяти]], [[Бинарный поиск в упорядоченном массиве]].

### Сортировки

- **Устойчивость:** равные ключи сохраняют исходный взаимный порядок. Компаратор `<0/0/>0` задаёт порядок; булево равенство не заменяет его.
- **Обменный алгоритм слайда «Bubble»:** сравнивает все $j<i$ с позицией $i$, выполняет $n(n-1)/2$ сравнений, время $\Theta(n^2)$ и дополнительную память $O(1)$ элементов. Это не классический соседний пузырёк и не устойчивый вариант.
- **Вставки:** отсортированный префикс расширяется сдвигами и вставкой сохранённого ключа. Лучшее время $\Theta(n)$, худшее $\Theta(n^2)$, среднее квадратично при равномерной перестановке разных ключей. Строгое сравнение сохраняет устойчивость; память $O(1)$ элементов.
- **Слияние:** две отсортированные половины объединяются за $\Theta(n)$, $T(n)=2T(n/2)+\Theta(n)=\Theta(n\log n)$, дополнительная память $O(n)$ и стек $O(\log n)$. Выбор левой части при равенстве сохраняет устойчивость.
- **Quicksort:** при сбалансированном разделении разных ключей время $\Theta(n\log n)$, при крайних $T(n)=T(n-1)+\Theta(n)=\Theta(n^2)$. Среднее требует модели. Разбиение Хоара обычно неустойчиво; стек $O(\log n)$ при балансе, $O(n)$ в худшем случае. Опору нужно сохранять значением. Трёхпутевой вариант с последовательными группами устойчив и обрабатывает все равные ключи за $\Theta(n)$; опубликованное владение массивами может дать $O(n^2)$ пиковой памяти при вырожденной рекурсии, $O(n)$ при балансе.
- **Шелл:** вставки по убывающим шагам с последним шагом 1; время зависит от последовательности, для показанного обменного цикла дополнительная память $O(1)$ элементов. Таблица слайдов не задаёт достаточных условий для универсальных средних оценок; полный теоретический анализ в лекции отсутствует.
- **Подсчёт:** для целочисленного диапазона ширины $K$ время $\Theta(n+K)$, у устойчивого варианта память $O(n+K)$. $K$ — диапазон, не число встретившихся значений.
- **Поразрядная LSD:** устойчиво сортировать по разрядам от младшего к старшему. При $R$ разрядах основания $b$ время $\Theta(R(n+b))$, память $O(n+b)$; при фиксированных $b,R$ время линейно по $n$. Приведённый код рассчитан на неотрицательные целые.
- **Другие названия в лекции:** выбор и Gnome — квадратичные по таблице, Heap — $O(n\log n)$ по среднему и худшему времени с $O(1)$ дополнительными элементами; Comb, Bucket и TimSort упомянуты без полного разбора. Heap означает пирамидальную сортировку, Radix — поразрядную. Формулы фрагмента статьи о $(h,1)$-Shell Sort и ограничения его контекста сохранены в подробной теме.

Подробно: [[Сортировки — сравнения, устойчивость и реализации]].

### Полный перебор и кластерные маски

- **Число вариантов:** $k$ полных циклов по $n$ дают $n^k$ при фиксированном $k$; независимые $n$ выборов по $n$ вариантов — $n^n$; перестановки различных индексов — $n!$; $k$-элементные подмножества — $\binom nk$; все подмножества — $2^n$.
- **Два кластера:** маска длины $n$ выбирает один из двух кластеров для каждой позиции, всего $2^n$ масок. Две дают пустой кластер; без различения имён кластеров при $n\ge1$ непустых разбиений $2^{n-1}-1$.
- **Критерий источника:** $\mu(C)=|C|^{-1}\sum_{x\in C}x$, $s(C)=\sum_{x\in C}|x-\mu(C)|$; минимизируется $s(C_0)+s(C_1)$ при непустых кластерах. Центр в источнике — среднее, а не медиана.
- **Итератор:** двоичный счётчик масок с переносом справа налево; состояние $O(n)$, инкремент в худшем $O(n)$, построение полной маски $\Theta(n)$. При геометрическом росте Vector и освобождении временных данных перебор занимает $\Theta(n2^n)$ времени и $O(n)$ живой дополнительной памяти. Указанная в слайдах граница $O(n^22^n)$ возможна при линейной стоимости каждого добавления.
- **Граница интерпретации:** экспоненциальный перебор не доказывает NP-полноту задачи. В лекции 11 определения классов, сводимости и доказательство NP-полноты отсутствуют; её заголовок не заменяет эти результаты.

В конспектах разобраны расхождения слайдов: зависимые от платформы размеры и форматы печати, смешение указателя на строку с буфером на 100 байт, несогласованные оценки памяти коллекций, запись адреса вместо значения, возврат «не найдено» после успешного поиска и преждевременное удаление элемента окна. Повторы кода объединены с сохранением различий версий и пояснением исправлений. Упражнения, вопросы аудитории и организационные указания исключены.

Теоретическое содержание доступных слайдов перенесено; заявленная полнота относится к этим двум PDF. Показанные с пропусками функции `resize`, `meanValue`, `meanListValue` и часть API контейнеров не имеют в них полной реализации. Поэтому соответствующие фрагменты остаются схемами и контрактами, а не законченной библиотекой. Идея сохранения суммы окна в существующей заметке происходит из прежнего конспекта, не из этих презентаций. Год в имени файла не используется для определения даты лекции.
