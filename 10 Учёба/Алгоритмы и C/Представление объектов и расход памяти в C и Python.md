# Представление объектов и расход памяти в C и Python

Размер полезного значения и расход памяти на объект — разные величины. Массив C хранит значения подряд, а `list` в CPython хранит ссылки на объекты с собственными служебными данными. Поэтому сравнивать нужно представления и способ измерения, а не только названия типов.

## Что именно измеряется

`sizeof` в C даёт размер типа или объекта в байтах C. Для настоящего массива это размер всех элементов, для указателя — размер самого указателя. Длина выделенного через `malloc` массива из указателя не восстанавливается.

В Python `sys.getsizeof(obj)` учитывает память, непосредственно относимую к объекту, без рекурсивного включения объектов по его ссылкам. Поэтому размер списка и полный расход памяти на список с его значениями — разные измерения. Это уточнение подтверждено [документацией `sys.getsizeof`](https://docs.python.org/3.14/library/sys.html#sys.getsizeof).

Во втором строковом примере слайдов используется другой инструмент — `pympler.asizeof.asizeof`. Он оценивает суммарный размер с учётом достижимых объектов, общих ссылок и выравнивания; повторно встреченный объект учитывается один раз. Его числа нельзя смешивать с `getsizeof` как результаты одного метода. См. [документацию Pympler](https://pympler.readthedocs.io/en/latest/asizeof.html).

Все числа ниже — наблюдения из презентации, а не гарантии языка или результаты новой серии измерений. Версия интерпретатора, платформа, сборка и способ создания коллекции влияют на результат.

## Логические значения

На слайде для `True` и `False` указан размер 28 байт. При этом строка вывода для `False` по ошибке снова измеряет `True`; корректное выражение для неё — `sys.getsizeof(False)`.

Отдельный объект не создаётся для каждого появления `True`: пример `id(True) == id([True][0])` показывает ссылку на тот же объект. В CPython есть два логических объекта — `True` и `False`, что подтверждает [документация Boolean Objects](https://docs.python.org/3/c-api/bool.html). Миллион ссылок на `True` не означает миллион разных объектов по 28 байт.

График сравнивает примерно 8 миллионов байт для миллиона ссылок в списке с примерно миллионом байт для массива C при `sizeof(bool)==1`. Это объясняется размером ссылок в показанной 64-битной среде. Служебные поля, запас вместимости и два общих логических объекта учитываются отдельно.

## Целые числа

| Выражение Python на слайде | Указанный размер, байт |
|---|---:|
| `1` | 28 |
| `2_147_483_647` | 32 |
| `2_147_483_648` | 32 |
| `int(1e21)` | 36 |
| `int(1e36)` | 40 |

Размер целого объекта может расти вместе с величиной числа. В примерах C размер выбранного целочисленного типа фиксирован: большее значение требует подходящего типа с достаточным диапазоном. Записи `int(1e21)` и `int(1e36)` сначала создают вещественное значение и затем преобразуют его в целое; это не способ гарантированно задать произвольное большое десятичное целое без округления.

В слайде есть несогласованность: подпись говорит о пятикратной разнице, а график для миллиона элементов показывает примерно 36 миллионов байт против 4 миллионов. В модели «8 байт ссылки + отдельный 28-байтовый объект на число» получается около 36 байт на элемент против 4, то есть примерно девятикратная разница. Это объяснение графика, а не универсальный коэффициент: общие объекты, размеры чисел и резерв списка меняют итог.

## Вещественные числа

Для `0.1`, `sys.float_info.max` и `sys.float_info.max + 2` на слайде показано по 24 байта. В данном представлении изменение значения не увеличивает размер объекта `float`.

Название `more_than_max_float` у последнего выражения вводит в заблуждение: в показанной арифметике прибавление 2 к числу порядка $10^{308}$ слишком мало, чтобы изменить представимое значение, и после округления получается то же число. Пример не демонстрирует хранение конечного значения выше максимального.

График даёт около 32 миллионов байт для миллиона отдельных вещественных объектов со ссылками и около 8 миллионов для массива `double`: модель $24+8$ против 8 байт объясняет указанное четырёхкратное отношение. Условия сравнения и учёт общих объектов остаются существенными.

## Символы и строки

В C строка — последовательность элементов `char` с завершающим `\0`; отдельного встроенного типа `string` нет. В Python односимвольный текст также является строкой, а не отдельным типом `char`.

| Строка | `sys.getsizeof` на слайде, байт |
|---|---:|
| `""` | 41 |
| `"w"` | 42 |
| `"ы"` | 60 |
| `"ww"` | 43 |
| `"цы"` | 62 |
| `"wы"` | 62 |

Накладные расходы заметны уже у пустой строки. В CPython внутреннее представление зависит от набора символов: для данных выбирается ширина 1, 2 или 4 байта на кодовую точку. Это не тождественно хранению UTF-8; наличие кириллицы может изменить представление всей строки. Смысл различий подтверждён [PEP 393](https://peps.python.org/pep-0393/); точные размеры конкретной сборки из PEP не следуют.

В отдельном примере Pympler показаны:

| Выражение для `asizeof.asizeof` | Результат на слайде, байт |
|---|---:|
| `"hello"` | 48 |
| `"Hello wor"` | 56 |
| `"Hello world!"` | 56 |
| `[]` | 56 |
| `["hello", "world"]` | 168 |

На слайде некоторые подписи вывода ошибочно повторяют `Size of []`; в таблице оставлены фактически измеряемые выражения. Одинаковая оценка двух строк разной длины здесь согласуется с округлением размеров при выравнивании, а не означает, что любые строки занимают одинаковую память.
