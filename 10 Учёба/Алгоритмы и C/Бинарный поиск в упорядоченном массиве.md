# Бинарный поиск в упорядоченном массиве

[[Алгоритмы и C]]

Бинарный поиск отбрасывает примерно половину оставшегося диапазона после сравнения с его серединой. Он требует заранее упорядоченного массива и согласованного трёхзначного компаратора.

## Условия и последовательность

Пусть массив отсортирован по возрастанию согласно `cmp(a,b)`: отрицательное значение означает $a<b$, ноль — равенство, положительное — $a>b$. Булевый `EqualsFunc`, возвращающий только «равны/не равны», не сообщает сторону продолжения поиска.

Храним полуинтервал `[low, high)`, первоначально `[0,n)`. Пока он непуст, берём `mid = low + (high-low)/2`:

1. Если `arr[mid]` равен ключу, возвращаем найденную позицию.
2. Если `arr[mid]` меньше ключа, продолжаем в `[mid+1, high)`.
3. Если больше — в `[low, mid)`.

**Промежуточное объяснение корректности:** если средний элемент меньше ключа, все элементы слева не больше среднего и тоже не подходят; симметрично исключается правая часть при большем среднем. После шага ключ, если он существует, остаётся в текущем диапазоне. Размер диапазона строго уменьшается, поэтому цикл заканчивается. Пустой диапазон означает отсутствие ключа.

## Исправленный фрагмент C

Это тот же алгоритм слайда с явно исправленными границами и условиями. Используется API существующего [[Vector — устройство и операции|Vector]], а не добавленная реализация контейнера.

```c
typedef int (*CompareFunc)(const void *, const void *);

void *binarySearch(Vector *vector, const void *key, CompareFunc cmp) {
    if (vector == NULL || key == NULL || cmp == NULL) return NULL;
    size_t low = 0, high = vector->size;
    while (low < high) {
        size_t mid = low + (high - low) / 2;
        void *item = getVectorItem(vector, mid);
        int order = cmp(item, key);
        if (order == 0) return item;
        if (order < 0) low = mid + 1;
        else high = mid;
    }
    return NULL;
}
```

Полуинтервал позволяет обработать пустой вектор без `size-1` и избежать беззнакового ухода ниже нуля. Возвращённый адрес принадлежит вектору и может потерять действительность при изменении буфера. При повторяющихся ключах возвращается некоторое вхождение, поиск первого вхождения здесь не обещается.

## Ошибки исходного фрагмента

- На первом слайде верхняя включительная граница равна `vector->size` вместо последнего допустимого индекса. На следующем она заменена на `size-1`, но другие ошибки остались.
- `if (cmp(item,data))` принимает любой ненулевой результат за равенство; в трёхзначном компараторе проверяют `==0`.
- Условие `while(index > 0 && low <= up)` завершает цикл после первого неуспешного сравнения при `index=-1`, а после успеха может, наоборот, продолжать. Цикл должен продолжаться, пока диапазон непуст и ответ ещё не возвращён.
- `do…while` выполняет тело даже при пустом массиве. Средина `(low+up)/2` также может переполниться; используется разность границ.

Исправления отмечены явно, поскольку оценка правильного бинарного поиска не доказывает корректность опубликованного ошибочного кода.

## Логарифмическая оценка

После $t$ шагов остаётся не более примерно $n/2^t$ позиций. Пока $n/2^t\ge1$, возможно продолжение; число шагов ограничено величиной порядка $\log_2n$.

При $O(1)$ доступе по индексу и сравнении:

- худший случай при $n\ge2$ — $\Theta(\log n)$;
- лучший для непустого массива — $\Theta(1)$, если ключ сразу в середине;
- дополнительная память итеративного варианта — $\Theta(1)$.

На слайде одновременно стоят $O(\log n)$, $\Omega(1)$ и $\Theta(\log n)$. Их следует связывать с конкретным случаем; нельзя объявлять время каждого успешного поиска точным $\Theta(\log n)$. На связном списке доступ к середине не константный, поэтому оценку массива нельзя переносить без изменения.
