# Vector — устройство и операции

> [!abstract] Суть
> Vector скрывает управление буфером за операциями контейнера. Первая версия хранит int8_t, обобщённая — элементы заданного размера, копируемые как байты.

## Типизированная версия

```c
#include <stdint.h>
#include <stddef.h>
#include <stdlib.h>
#include <string.h>

typedef struct {
    int8_t *data;
    size_t size;
    size_t capacity;
} Vector;

Vector *createVector(void);
int appendVectorItem(Vector *vector, int8_t *el);
void *getVectorItem(Vector *vector, size_t index);
int setVectorItem(Vector *vector, size_t index, int8_t *value);
int8_t *popVectorItem(Vector *vector, size_t index);
long findVectorItem(Vector *vector, int8_t *value);
int vectorFree(Vector *vector);
```

`size` — занятые места, `capacity` — выделенные. Инвариант `size <= capacity`; действительные индексы `0 <= i < size`. В исходнике используются разные варианты имён API; здесь сохранены имена варианта лекции 6.

У операций разные результаты: `get` возвращает адрес элемента внутри контейнера, `pop` — отдельно выделенную копию удаляемого значения, а `append`/`set` в показанном интерфейсе возвращают код состояния. Заготовки слайдов местами объявляют результат `appendVectorItem` как `Vector *`, тогда как реализация возвращает `0` или `-1`; здесь согласован целочисленный вариант из реализации. В объявлениях без параметров используется форма `(void)`, чтобы явно обозначить отсутствие аргументов в C11/C17.

### Создание

Следующий фрагмент использует положительную начальную вместимость `MIN_SIZE`, задаваемую программой:

```c
Vector *createVector(void) {
    Vector *vector = malloc(sizeof *vector);
    if (vector == NULL) return NULL;
    vector->data = malloc(MIN_SIZE * sizeof *vector->data);
    if (vector->data == NULL) {
        free(vector);
        return NULL;
    }
    vector->size = 0;
    vector->capacity = MIN_SIZE;
    return vector;
}
```

При отказе второго выделения освобождается уже созданная структура. У исходного `malloc(MIN_SIZE*1)` единица относится именно к `int8_t` на восьмибитной платформе; запись через `sizeof` выражает тип явно.

### Добавление

```c
int resize(Vector *vector, int change);

int appendVectorItem(Vector *vector, int8_t *el) {
    if (vector == NULL || el == NULL) return -1;
    if (resize(vector, 1) != 0) return -1;
    vector->data[vector->size] = *el;
    ++vector->size;
    return 0;
}
```

`resize` здесь — зависимость примера, её реализация в PDF не приведена. Контракт — обеспечить место для добавления, сохранив прежнее состояние при отказе. `change` должен допускать отрицательное значение для показанного ниже удаления. Корректная реализация также контролирует переполнение размера выделения.

Первая свободная ячейка — `data[size]`. Записывается `*el`, значение, а не `el`, адрес. Предполагается, что `el` не является указателем внутрь буфера, который может переместить `resize`; для такого alias исходная последовательность действий небезопасна.

### Удаление с возвращаемой копией

```c
int8_t *popVectorItem(Vector *vector, size_t index) {
    if (vector == NULL || index >= vector->size) return NULL;
    int8_t *copy = malloc(sizeof *copy);
    if (copy == NULL) return NULL;
    int8_t *item = getVectorItem(vector, index);
    memcpy(copy, item, sizeof *copy);
    for (size_t i = index; i + 1 < vector->size; ++i) {
        int8_t *src = getVectorItem(vector, i + 1);
        setVectorItem(vector, i, src);
    }
    --vector->size;
    (void)resize(vector, -1);
    return copy;
}
```

Фрагмент предполагает, что `get`/`set` корректны для проверенных индексов, `set` не меняет буфер, а необязательное сжатие при отказе оставляет действующий буфер. Без этих условий игнорировать ошибки вспомогательных функций нельзя. Возвращённая копия независимо выделена; вызывающий делает `free(copy)`. Сдвиг элементов делает удаление из начала $O(n)$. Тела `get`, `set`, `find`, `vectorFree`, как и `resize`, в PDF полностью не даны; здесь не добавляются реализации сверх источника.

## Обобщённое хранение через void *

`void *` хранит указатель на объект без конкретного типа объекта. Пример `int x=10; void *p=&x; int y=*(int *)p;` корректен, потому что реальный объект — живой `int`. Непосредственное `*p=5` недопустимо; приведение типа не создаёт объект и само по себе не делает произвольный адрес корректным. Указатели на функции — отдельная категория, не обещанная этим правилом `void *`.

```c
typedef struct {
    void *data;
    size_t elem_size;
    size_t size;
    size_t capacity;
} GenericVector;
```

В PDF обе версии названы `Vector`; для совместного чтения здесь обобщённый тип переименован, это альтернативные представления.

Лекция 5 завершает изложение объявлением `Vector *vectorCreate(size_t elem_size)` и полями `data`, `size`, `elem_size`, `capacity`. В лекции 6 конструктор обобщённой версии называется `createVector(size_t elem_size)`, а порядок полей немного иной. Смысл одинаков: размер элемента задаётся при создании контейнера и должен сохраняться в `elem_size`. Имена конструкторов из разных примеров не следует смешивать как единственный готовый API.

Адрес элемента вычисляется как `(char *)data + i * elem_size`. Приведение к символьному указателю делает шаг равным байту C; арифметика над `void *` не является стандартной операцией C.

```c
#include <stdlib.h>
#include <string.h>
#include <stdio.h>

void generic_address_demo(void) {
    const size_t elem_size = sizeof(int);
    int *arr = malloc(10 * elem_size);
    if (arr == NULL) return;
    int value = 4;
    memcpy((char *)arr + 3 * elem_size, &value, elem_size);
    printf("Value: %d\n", *(int *)((char *)arr + 3 * elem_size));
    free(arr);
}
```

В первой свободной ячейке обобщённого вектора запись заменяется на `memcpy((char *)data + size*elem_size, el, elem_size)`. Создание выделяет `capacity*elem_size`, а возвращаемая копия при удалении — `elem_size` байтов. Перед умножением проверяются допустимые размеры; `memcpy` не разрешает перекрывающиеся области.

| Содержимое элемента | Размер элемента |
|---|---|
| `int`, `short`, `double`, `char` | Соответствующий `sizeof`, не зафиксированные 4/2/8/1 кроме `sizeof(char)==1` |
| `struct Point` | `sizeof(struct Point)` |
| Указатель на строку `char *` | `sizeof(char *)`; копируется только адрес |
| Встроенный строковый буфер до 100 байтов | 100; это другой способ хранения, не размер `char *` |

Договорённость PDF «для строки char* 100 байт» смешивает два последних варианта. Контейнер должен выбрать один. Байтовое копирование структуры с полем-указателем не копирует выделенные данные за ним. Владение вложенными ресурсами и срок годности адреса, выданного `get`, должны быть определены отдельно.

## Исправления по оригинальным слайдам

В добавлении слайд записывает `vector->data[vector->size] = el`, то есть адрес вместо значения; в типизированном варианте выше записано `*el`. В обобщённом варианте вместо присваивания используется показанный на слайде `memcpy` с размером `elem_size`. Аналогично размер выделения при создании и размер копии при удалении меняются с одного `int8_t` на нужное число байтов.

В примере адресации индекс 3 даёт смещение 12 байт только при `sizeof(int)==4`; общая формула остаётся `3 * elem_size`. Исходное `char* → 100 байт` не задаёт размер указателя: 100 может быть вместимостью отдельного строкового буфера. Тела `resize`, обобщённых операций и части API в слайдах по-прежнему не приведены; фрагменты не представлены здесь как законченная библиотека.
