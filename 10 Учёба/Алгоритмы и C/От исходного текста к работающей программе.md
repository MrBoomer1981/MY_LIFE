# От исходного текста к работающей программе

> [!abstract] Суть
> Исходный код описывает вычисление, но процессор исполняет машинные инструкции. Сборка переводит описание в исполняемый файл и связывает его части.

## Четыре этапа сборки C

| Этап | Преобразование | Назначение |
|---|---|---|
| Препроцессинг | Исходный текст → подготовленный текст | Обработка включений, макросов и условной компиляции |
| Компиляция | Подготовленный текст → ассемблерное представление | Проверка языка и перевод вычислений |
| Ассемблирование | Ассемблер → объектный файл | Кодирование машинных инструкций |
| Линковка | Объектные файлы и библиотеки → программа | Разрешение внешних ссылок и объединение частей |

Объявление функции сообщает её имя и тип, а определение содержит реализацию. Поэтому файл может пройти компиляцию, но не пройти линковку, если нужная реализация отсутствует. Заголовок обычно предоставляет объявления, а не заменяет библиотеку с реализацией.

Makefile описывает зависимости результатов от исходных файлов. Идея сборки по зависимостям — пересоздавать устаревшие части, а не безусловно всё целиком.

## Выполнение и управление потоком

Выражения вычисляют значения; операторы управляют действиями. Условие выбирает ветвь, цикл повторяет действия, функция выделяет вычисление с параметрами и результатом. В условиях C ноль считается ложью, ненулевое значение — истиной.

Область видимости определяет, где имя доступно в исходном коде. Время жизни определяет, когда соответствующий объект существует. Эти понятия связаны, но не тождественны: динамически выделенный объект может пережить выполнение функции, которая его создала.

## Компиляция и интерпретация

Компилятор переводит программу из одного представления в другое. Интерпретатор выполняет программу, представленную некоторым языком или промежуточным кодом. Это свойства реализации, а не взаимоисключающие ярлыки для языков: в CPython исходный Python-код компилируется в байткод, который затем исполняется интерпретатором.

## Пример полного пути сборки

```c
#include <stdio.h>
#define LAST 10

int main(void) {
    int sum = 0;
    for (int i = 1; i <= LAST; ++i) {
        sum += i;
    }
    printf("sum = %d\n", sum);
    return 0;
}
```

Программа печатает `sum = 55`. `#include <stdio.h>` предоставляет объявления стандартного ввода-вывода, включая `printf`, а не вставляет в исходник машинную реализацию библиотеки. Объектный макрос `LAST` заменяется токеном `10` при препроцессинге; комментарии удаляются. Это обработка токенов по правилам препроцессора, а не произвольная замена всех совпадений внутри строк и имён.

```bash
gcc -Wall -save-temps test.c -o test
gcc -E main.c -o main.i
gcc -S main.i -o main.s
gcc -c main.s -o main.o
gcc main.o -o main
```

Первая команда сохраняет промежуточные файлы. Остальные показывают четыре стадии по отдельности. Объектный `.o` содержит машинный код и сведения для связывания, но обычно не является самостоятельной программой. Вызов `printf` ещё требует разрешения внешнего символа; это одна из причин, почему файл нельзя просто запустить.

Внутри компилятора текст разбивается на лексемы: `a = 2;` — имя, `=`, число, `;`. Синтаксический анализ строит AST; в `temp1 + temp2` операция сложения соединяет два операнда. Дальнейший перевод и оптимизация дают целевой код.

## Статическая и динамическая связь

Статическая библиотека `.a` передаёт нужные объектные модули в исполняемый файл. Файл может стать больше, но это не гарантирует отсутствия всех прочих внешних зависимостей. Динамическая библиотека (`.so` в Linux, `.dylib` в macOS, `.dll` в Windows) остаётся отдельной; для выполнения нужны подходящая библиотека и механизм её загрузки/связывания. Линковка не всегда буквально копирует реализацию `printf` в программу.

## Инструменты и запуск

В источнике перечислены GCC, Clang и MSVC: распространённые реализации для Linux, macOS и Windows соответственно, без жёсткой привязки к одной ОС. В стандартной конфигурации macOS команда `gcc` может запускать Apple Clang. Исторические ориентиры PDF: C — Dennis Ritchie, начало 1970-х (1972), C++ — развитие «C с классами», название C++ появилось в 1983 году.

```bash
gcc --version
gcc test.c -o test
./test
```

Приведённые в PDF команды установки — `brew install gcc` для Homebrew и `sudo apt install build-essential` для Debian/Ubuntu. Это примеры способов получения инструментов, они здесь не выполнялись. Упомянутое расширение C/C++ для VS Code помогает с диагностикой и отладкой.

Компиляция и интерпретация могут сочетаться. Упрощение PDF «Python выполняется по строкам» не описывает CPython: он предварительно получает байткод. `print(1)` в интерактивном сеансе выводит 1 после обработки введённой команды. PyPy, MicroPython и Brython — альтернативные реализации с разными задачами; обещание ускорения PyPy в 2–5 раз — частный ориентир источника, не гарантия. GIL в обычной сборке CPython ограничивает одновременное исполнение Python-кода потоками, но не запрещает всякий параллелизм; поведение зависит от реализации и сборки.

## Makefile и диагностика

```makefile
TARGET = test
CC = gcc
CFLAGS = -Wall -Wextra -O2
SRC = test.c

all: $(TARGET)

$(TARGET): $(SRC)
	$(CC) $(CFLAGS) $(SRC) -o $(TARGET)

run: $(TARGET)
	./$(TARGET)

clean:
	rm -f $(TARGET)
```

Строки рецептов начинаются табуляцией. `make run` сначала при необходимости собирает цель, затем запускает её; `make clean` удаляет собранную программу. `-Wall -Wextra` включают группы предупреждений (не абсолютно все), `-O2` — оптимизацию. Для крупных проектов в PDF названы CMake, Ninja, Meson и Bazel.

| Диагностика из PDF | Смысл |
|---|---|
| `No rule to make target 'test1.c', needed by 'test'` | Нет требуемого файла и правила его получения; возможна опечатка |
| `test.c:6:19: expected ';' at end of declaration` | Место диагностики: файл, строка, столбец; вероятно, пропущена `;` |
| `use of undeclared identifier 'i'` | Имя недоступно в этой точке, например объявлено в заголовке уже завершившегося `for` |
| Неопределённый символ `main` | В обычной hosted-программе при связывании отсутствует требуемая точка входа C |

Первая ошибка часто вызывает последующие, поэтому диагностику разумно читать начиная с неё. Требование `main` относится к обычной среде выполнения C: отдельный объектный файл, библиотека или freestanding-среда не обязаны содержать её.
