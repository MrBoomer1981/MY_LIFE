# Чтение чисел из файла и скользящее среднее

> [!abstract] Суть
> Скользящее среднее последовательно обрабатывает соседние окна данных. Пример объединяет чтение файла, контейнеры, проверку диапазонов и очистку ресурсов.

## Смысл сглаживания

Для входа `1 2 3 4 5` и окна 3 окна `[1 2 3]`, `[2 3 4]`, `[3 4 5]` дают средние `2 3 4`. При длине входа $n$ и окна $w\le n$ полных окон $n-w+1$. Выход короче входа на $w-1$; неполные края в этой постановке не обрабатываются. Итоговые числа предполагается записывать в файл, но отдельного кода записи PDF не содержит.

Математический смысл среднего полного окна:

$$
y_i=\frac{1}{w}\sum_{j=0}^{w-1}x_{i+j},\qquad 0\le i\le n-w.
$$

Иллюстрация оригинальной лекции сравнивает сглаживание по 20 соседям, по выбранному автором «оптимальному» числу соседей и по 80 соседям. Большее окно сильнее сглаживает локальные колебания, но может скрывать изменения ряда. Правило выбора «оптимального» размера и исходные точки графика не предоставлены, поэтому это иллюстрация эффекта окна, а не воспроизводимый расчёт конкретных кривых.

## Исходная версия с обычным массивом

В первой версии лекции `read_array` возвращает `int8_t *`. Одного адреса недостаточно для дальнейшего прохода: длину нужно передать отдельно. Поэтому интерфейс меняется с `read_array(char *filename)` на `read_array(char *filename, size_t *arr_size)`. Выходной указатель `arr_size` должен быть действительным, счётчик устанавливается в ноль до первого добавления; после успеха вызывающая сторона получает буфер и его длину, а затем освобождает буфер.

Во время чтения исходная схема хранит место для очередного элемента и после каждого завершённого числа увеличивает буфер на один `int8_t`. Она иллюстрирует связь двух действий: запись `arr[*arr_size]` и увеличение `(*arr_size)`. Сам `malloc` или `realloc` не ведёт пользовательский счётчик длины. Варианты слайдов, названные «правильным кодом», всё ещё содержат опечатки и пропуски; ниже используется исправленная общая логика, уже с контейнером.

У первой версии сглаживания интерфейс также разделяет данные и размеры:

```c
int8_t *smoothV1(const int8_t *arr, size_t arr_size,
                 size_t *size_out, uint8_t window_size);
```

Это объявление схемы из слайдов с переносимым именем `uint8_t` вместо `u_int8_t`. Тело выполняет ту же последовательность, что `smoothV2` ниже: проверяет окно, обнуляет выходной счётчик, создаёт массив результата, копирует каждое окно, вызывает `meanValue`, записывает среднее и увеличивает выходной размер. В исходной реализации после каждого результата ещё вызывается `realloc`. Таким образом, есть две независимые затраты: копирование и обработка окон и частые перевыделения массива результата. `Vector` скрывает вторую группу действий за `append`, но не устраняет первую.

## Чтение символов и накопление числа

Псевдокод источника: создать контейнер → открыть файл → читать символы до `EOF` → накопить символы очередного числа → на пробеле преобразовать и добавить значение → очистить буфер → после EOF обработать оставшееся число → закрыть файл.

`fgetc` возвращает `int`: так можно отличить `EOF` от любого байта. `char digit_str[5]` в примере рассчитан на запись −128: четыре символа и `\0`. Несколько пробелов подряд не должны создавать нулевые элементы. Последнее число может не иметь пробела после себя, поэтому оставшийся буфер обрабатывается отдельно.

Ниже та же схема из PDF с исправлениями ошибок. Фрагмент использует типизированный `Vector` и его объявленные операции из [[Vector — устройство и операции]]. Он не добавляет отсутствующую в источнике реализацию контейнера.

```c
#include <stdio.h>
#include <stdlib.h>
#include <stdint.h>
#include <stddef.h>
#include <errno.h>

static int append_number(Vector *arr, const char *text) {
    char *end;
    errno = 0;
    long value = strtol(text, &end, 10);
    if (end == text || *end != '\0' || errno == ERANGE ||
        value < INT8_MIN || value > INT8_MAX) {
        return -1;
    }
    int8_t item = (int8_t)value;
    return appendVectorItem(arr, &item);
}

Vector *readArrayV2(const char *filename) {
    if (filename == NULL) return NULL;
    FILE *file = fopen(filename, "r");
    if (file == NULL) return NULL;
    Vector *arr = createVector();
    if (arr == NULL) {
        fclose(file);
        return NULL;
    }
    char digit_str[5] = "";
    size_t len = 0;
    int symbol_code;
    while ((symbol_code = fgetc(file)) != EOF) {
        if (symbol_code == ' ') {
            if (len != 0) {
                if (append_number(arr, digit_str) != 0) goto fail;
                len = 0;
                digit_str[0] = '\0';
            }
        } else {
            if (len + 1 >= sizeof digit_str) goto fail;
            digit_str[len++] = (char)symbol_code;
            digit_str[len] = '\0';
        }
    }
    if (ferror(file)) goto fail;
    if (len != 0 && append_number(arr, digit_str) != 0) goto fail;
    if (fclose(file) != 0) {
        vectorFree(arr);
        return NULL;
    }
    return arr;
fail:
    fclose(file);
    vectorFree(arr);
    return NULL;
}
```

Фиксированный буфер сохраняет ограничение исходной схемы: длинная текстовая запись отвергается даже при численно допустимом значении, например с большим числом ведущих нулей. Разделитель здесь — именно пробел, как в исходном алгоритме. Обработка любых пробельных символов не обещается. Проверки `end` отличают неверный текст от корректного нуля; диапазон проверяется до приведения к `int8_t`. Преобразование 128 в −128 не является переносимым способом проверки ошибки.

## Состояния входа и ресурсные ошибки

Исходные примеры чтения охватывают положительные `1 2 3 4 5`, отрицательные `-1 -2 -3 -4 -5`, смешанные `-1 1 -2 2 3`, нули `0 0 1 0 0`, несколько пробелов и ведущие нули `01 02 03`. Важны также пустой файл и файл из пробелов, отсутствие файла, границы −128/127, недопустимые −129/128, буквы, записи длиной пять и шесть символов и большие объёмы в 10 тысяч либо 10 миллионов чисел. Это описание различных состояний входа и нагрузки из лекции, а не задание на тестирование.

Исправления исходного чтения:

- С пробелом сравнивается `symbol`, не `strlen(digit_str)`: длина строки и код символа — разные величины.
- Перед записью проверяется место и для символа, и для `\0`: при длине 4 в буфере на 5 элементов новый символ уже не помещается вместе с терминатором.
- При отказе `fopen` ранее выделенный контейнер не должен утекать; здесь файл открывается первым, а все последующие неуспехи освобождают оба ресурса.
- При чтении в обычный динамический массив адрес не хранит длину; нужен отдельный `size_t *arr_size`. Вектор хранит `size` внутри.
- Увеличивается `(*arr_size)++`, не `*arr_size++`; неудачный `realloc` обрабатывается через временный указатель.

## Сглаживание с копированием окна

Фрагмент следует исходной версии `smoothV2`; `meanValue` в PDF вызывается, но её тело отсутствует. Конкретное правило округления среднего при возвращении `int8_t` поэтому не восстанавливается догадкой. Суммирование внутри неё должно учитывать диапазон промежуточной суммы.

```c
int8_t meanValue(const int8_t *window, size_t window_size);

Vector *smoothV2(Vector *arr, const uint8_t window_size) {
    if (arr == NULL || window_size < 2 || window_size >= arr->size) {
        return NULL;
    }
    Vector *arr_out = createVector();
    if (arr_out == NULL) return NULL;
    int8_t window[UINT8_MAX];
    for (size_t i = 0; i <= arr->size - window_size; ++i) {
        for (size_t j = 0; j < window_size; ++j) {
            window[j] = *(int8_t *)getVectorItem(arr, i + j);
        }
        int8_t value = meanValue(window, window_size);
        if (appendVectorItem(arr_out, &value) != 0) {
            vectorFree(arr_out);
            return NULL;
        }
    }
    return arr_out;
}
```

Пример сохраняет контракт слайда: $2\le w<n$. Это строже математически возможного $w\le n$: окно, равное входу, могло бы дать одно среднее, но исходный интерфейс его отвергает. Статический верхний предел окна заменяет необязательный для некоторых реализаций C массив переменной длины; используется факт `uint8_t` с максимумом 255. Элементы входа здесь именно `int8_t`, не произвольные байтовые объекты.

`getVectorItem` возвращает адрес, поэтому в окно записывается `*(int8_t *)...`, а не сам указатель. Каждый раз копируется $w$ элементов и среднее вычисляется заново: при линейном подсчёте среднего получается $O((n-w+1)w)$.

## Окно-очередь из списка

Версия `smoothV3` в PDF дана с пропусками. Её последовательность сохранена как схема, а не выдана за готовую реализацию:

```text
создать arr_out и список list для окна
для каждого элемента входного вектора:
    appendItem(list, getVectorItem(arr, i))
    если listLength(list) > window_size:
        free(popItem(list, 0))
    если listLength(list) < window_size:
        перейти к следующему элементу
    value = meanListValue(list)
    appendVectorItem(arr_out, &value)
освободить list, вернуть arr_out
```

Сначала добавляется новое, потом удаляется лишнее и только после этого вычисляется среднее полного окна. Если удалить старое уже в момент достижения нужного размера до вычисления, останется на один элемент меньше.

`free(popItem(...))` корректно только при контракте, что `popItem` возвращает независимо выделенные данные во владение вызывающему; если список возвращает указатель прямо в буфер входного вектора, такое освобождение ошибочно. В исходном интерфейсе это не определено, поэтому нельзя объявить фрагмент полностью безопасным без уточнения реализации. Успех создания/добавления, выходы по ошибке и итоговое освобождение списка также требуют обработки.

В оригинальном `smoothV3` после добавления при `i < window_size - 1` цикл продолжается, а при первом достижении полного окна уже выполняется `popItem(list, 0)`. Значит, среднее считается по окну на один элемент короче требуемого. Выше удаление отложено до превышения длиной размера окна. В слайде также отсутствует итоговый `freeList`, а при ошибке добавления результата освобождается только выходной вектор. Это существенные отличия между исходным фрагментом и исправленной схемой.

После перехода к обобщённому вектору его создание требует `elem_size`; в последней версии слайда используется `createVector(arr->elem_size)`. Возвращаемый `int8_t value` при этом не превращается в элемент произвольного размера: данный алгоритм по-прежнему предназначен для `int8_t`. Если контейнер настроен на больший элемент, копирование `elem_size` байтов из адреса однобайтового `value` выходит за границы этого объекта. Обобщение хранения и обобщение арифметики — разные изменения; код слайдов завершает только первое.

Обновление очереди за $O(1)$ требует хвоста и известной длины; у структуры только с `head` и `elem_size` это не гарантировано. Даже с ними `meanListValue`, обходящий окно, сохраняет множитель $w$ в общей сложности. Список избавляет от полного копирования окна, но сам по себе не делает весь алгоритм линейным.

## Сохранение суммы окна

В самом PDF как дополнительное объяснение приведён способ хранить сумму: при сдвиге прибавлять новый элемент и вычитать ушедший. После первоначального суммирования среднего не требуется полный обход окна; при постоянной стоимости доступа к уходящему и входящему значениям весь проход занимает $O(n)$. Это материал предоставленного конспекта, хотя автор отмечает, что на лекции идея не разбиралась.
