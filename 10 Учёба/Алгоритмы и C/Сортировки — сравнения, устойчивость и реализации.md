# Сортировки — сравнения, устойчивость и реализации

[[Алгоритмы и C]]

Сортировка упорядочивает записи по ключу. Стоимость зависит от устройства алгоритма, исходного порядка, способа хранения и диапазона ключей. Одинаковое название не гарантирует одинаковых свойств разных реализаций.

## Классификация и устойчивость

Лекция 10 группирует алгоритмы по времени, дополнительной памяти, адаптации к уже упорядоченным данным и устойчивости.

- Простые квадратичные: пузырьковая, вставками, выбором, гномья.
- Сравнения с характерным ростом порядка $n\log n$: слияние, быстрая, пирамидальная; худший случай quicksort может быть квадратичным.
- Без сравнений ключей между собой: подсчёт, поразрядная, корзинная — с ограничениями на представление и диапазон ключей.
- Адаптивные: вставки и упомянутый гибрид TimSort, использующий упорядоченность входа.
- In-place: основная перестановка происходит в исходном массиве; стек рекурсии при оценке памяти всё равно учитывается.

**Уточнение названий:** `Heap Sort` — пирамидальная сортировка, а не «биномиальная»; `Gnome Sort` — гномья, а не сортировка «переполнением»; `Comb Sort` — расчёской, а не «пога»; `Radix Sort` — поразрядная, а не «радарная». Лекция перечисляет выбор, гномью, пирамидальную, расчёской, корзинную и TimSort, но не даёт для них полного кода и доказательств; отсутствующие реализации здесь не достраиваются.

**Устойчивость** означает сохранение исходного взаимного порядка записей с равными ключами. Если сравнивать только первые компоненты в `[(6,A),(3,X),(6,B),(1,K)]`, устойчивый результат обязан оставить `(6,A)` раньше `(6,B)`. Обмен `(6,A)` с `(1,K)` даёт `[(1,K),(3,X),(6,B),(6,A)]`: порядок двух шестёрок уже нарушен. Это пример слайда о неустойчивости разбиения quicksort.

Для всех последующих оценок сравнение и копирование элемента считаются $O(1)$. При размере записи $s$, растущем вместе с входом, байтовая стоимость копирования зависит от $s$.

## Обменный алгоритм, названный пузырьковым

Исходник сравнивает `arr[j]` с текущим `arr[i]` для всех $j<i$ и при необходимости меняет **эти две** позиции:

```c
/* Фрагмент источника, название сохранено. */
void BubbleSort(Vector *arr, CompareFunc cmp) {
    for (int i = 1; i < arr->size; i++) {
        void *v1 = getVectorItem(arr, i);
        for (int j = 0; j < i; j++) {
            if (cmp(getVectorItem(arr, j), v1) > 0)
                swapVectorItems(arr, i, j);
        }
    }
}
```

Здесь `CompareFunc` — трёхзначный компаратор; имя `EqualsFunc` в слайде не согласуется с проверкой `>0`. `v1` указывает на текущий элемент позиции `i`; после обмена содержимое по этому адресу меняется. Если `getVectorItem` возвращает копию, поведение уже другое.

Авторский проход для `[3,2,4,1]`:

| Шаг | Состояние |
|---|---|
| $i=1,j=0$ | `[2,3,4,1]` |
| $i=2,j=0$ и $j=1$ | `[2,3,4,1]`, обменов нет |
| $i=3,j=0$ | `[1,3,4,2]` |
| $i=3,j=1$ | `[1,2,4,3]` |
| $i=3,j=2$ | `[1,2,3,4]` |

**Уточнение:** классический пузырёк меняет соседние элементы. Опубликованный вариант — иной обменный алгоритм; подпись «стабильный» для него неверна. **Дополнительный контрпример:** `[2_A,2_B,1]` превращается в `[1,2_B,2_A]` после обмена позиций 0 и 2, что нарушает устойчивость.

Для опубликованных полных циклов число сравнений не зависит от исходного порядка:
$$\sum_{i=1}^{n-1}i=\frac{n(n-1)}2.$$
Поэтому при постоянной стоимости сравнения лучшее и худшее время $\Theta(n^2)$, дополнительная память $O(1)$ элементов, если сам обмен использует постоянное число временных элементов.

**Дополнительное объяснение корректности:** перед шагом $i$ префикс длины $i$ отсортирован. Последовательные сравнения переносят вставляемое значение в его место, а вытесненные значения постепенно сдвигают порядок через позицию $i$. После прохода префикс длины $i+1$ отсортирован. Это рассуждение относится к указанным обращениям к живой позиции `i`, а не к произвольному API обмена и копий.

## Сортировка вставками

Перед шагом $i$ префикс `[0,i)` отсортирован. Сохраняем копию `key = arr[i]`, сдвигаем вправо все элементы префикса, которые больше ключа, и записываем ключ в освободившееся место.

```c
/* Учебный фрагмент лекции; проверки API выделения опущены автором. */
void InsertionSort(Vector *arr, CompareFunc cmp) {
    for (int i = 1; i < arr->size; i++) {
        void *key = malloc(arr->elem_size);
        memcpy(key, getVectorItem(arr, i), arr->elem_size);
        int j = i - 1;
        while (j >= 0 && cmp(getVectorItem(arr, j), key) > 0) {
            setVectorItem(arr, j + 1, getVectorItem(arr, j));
            j--;
        }
        setVectorItem(arr, j + 1, key);
        free(key);
    }
}
```

Копия ключа необходима: иначе сдвиг мог бы перезаписать сохраняемое значение. `malloc` нужно проверять до `memcpy`; для массивов длиннее диапазона `int` индексы также требуют другого контракта. Фрагмент не является полностью обработанной по ошибкам библиотекой.

Разобранный пример `[3,2,4,1,5]`: на $i=1$ тройка сдвигается вправо, двойка занимает начало, получается `[2,3,4,1,5]`. Четвёрка уже на месте. При вставке единицы временно получаем `[2,3,4,4,5]`, затем `[2,3,3,4,5]`, затем `[2,2,3,4,5]`; запись ключа даёт `[1,2,3,4,5]`. Последняя пятёрка не требует сдвигов.

**Промежуточное доказательство:** сдвигаемые элементы остаются в прежнем порядке, все они больше `key`; все не сдвинутые слева не больше него. Вставка создаёт отсортированный префикс на один элемент длиннее. Строгое сравнение `>0` сохраняет порядок равных ключей, поэтому вариант устойчив.

Уже упорядоченный массив требует $\Theta(n)$ сравнений без сдвигов. Обратный порядок даёт $1+2+\cdots+(n-1)=\Theta(n^2)$ сдвигов. Средний случай при равномерной перестановке различных ключей тоже квадратичен; без модели входа «среднее» не определено. Дополнительная память — один элемент, $O(s)$ байтов, то есть $O(1)$ по $n$ при фиксированном $s$. Почти упорядоченные входы требуют мало сдвигов, что объясняет адаптивность.

## Сортировка слиянием

Рекурсивно сортируем две половины, затем сливаем их за линейное время. Границы кода — полуинтервалы `[left,right)`:

```c
void _mergeSort(Vector *arr, int left, int right, CompareFunc cmp) {
    if (right - left <= 1) return;
    int mid = left + (right - left) / 2;
    _mergeSort(arr, left, mid, cmp);
    _mergeSort(arr, mid, right, cmp);
    merge(arr, left, mid, right, cmp);
}
void MergeSort(Vector *arr, CompareFunc cmp) {
    _mergeSort(arr, 0, arr->size, cmp);
}
```

В слайде середина вычисляется как `(left+right)/2`; выше изменена лишь запись для избежания переполнения суммы. Полный контракт диапазона индексов остаётся необходимым. Блок-схема с `len(arr)<=2` неточна без отдельной сортировки пары: безопасная база опубликованного кода — длина не больше 1.

```text
merge(left, mid, right):
    создать temp длины right-left
    i=left, j=mid, k=0
    пока i<mid и j<right:
        если cmp(arr[i],arr[j])<=0: temp[k]=arr[i]; i++
        иначе: temp[k]=arr[j]; j++
        k++
    дописать остаток левой половины
    дописать остаток правой половины
    скопировать temp в arr[left:right]
    освободить temp
```

Это полная последовательность тела `merge` из лекции: две проверки границ, выбор меньшей головы, оба цикла дописывания хвостов и обратное копирование. При равенстве выбирается левая половина, что сохраняет устойчивость.

![[Слияние — дерево рекурсии.png]]

В примере исходник начинается `[1,0,2,3,...,20]`. Левая ветвь делится до `[1,0]`, затем `[1]` и `[0]`; обратное слияние даёт `[0,1]`, затем `[0,1,2]`. Стрелки вниз означают разделение, зелёные вверх — сборку упорядоченного результата.

Другой пример слайда: `[0,10,30]` и `[1,15,25]`. Сначала берём 0, потом 1, потом 10, поэтому при $i=2,j=1$ накоплен `[0,1,10]`. Далее идут 15,25 и оставшиеся 30; результат `[0,1,10,15,25,30]`. Последние шаги — промежуточное раскрытие начатого примера.

**Промежуточное доказательство слияния:** первые элементы двух оставшихся отсортированных частей — их минимумы. Меньший из них минимален среди всех ещё не выписанных элементов. Его добавление сохраняет порядок результата; когда часть кончилась, хвост второй можно дописать целиком. Индукция по рекурсивному разбиению даёт корректность всей сортировки.

На каждом уровне суммарно обрабатывается $\Theta(n)$ элементов, уровней $\Theta(\log n)$:
$$T(n)=2T(n/2)+\Theta(n)=\Theta(n\log n)$$
для стандартного слияния с копированием, включая уже отсортированные входы. Временный массив даёт $O(n)$ элементов, стек — $O(\log n)$. Пиковая дополнительная память $O(n)$: буферы завершённых дочерних слияний освобождаются до родительского. Проверки отказов `createVectorBySize` в слайде опущены.

## Быстрая сортировка с тремя массивами

Выбираем опорный элемент, проходим вход и в исходном порядке распределяем элементы в `left`, `equal`, `right`: меньше, равные и больше опорного. Рекурсивно сортируем только `left` и `right`, объединяем результаты в этом порядке.

```text
QuickSortStable(arr):
    если size<=1: вернуть arr
    pivot = arr[size/2]
    создать left, equal, right
    для каждого elem по порядку:
        cmp(elem,pivot)<0 → добавить в left
        cmp(elem,pivot)>0 → добавить в right
        иначе → добавить в equal
    left = QuickSortStable(left)
    right = QuickSortStable(right)
    создать out и объединить left + equal + right
    освободить временные коллекции; вернуть out
```

Это последовательность опубликованного `QuickSortStable`. Сохранение порядка добавления и устойчивость рекурсивных вызовов обеспечивают устойчивость: равные ключи попадают в одну группу и не переставляются внутри неё.

При сбалансированном разделении различных ключей $T(n)=2T(n/2)+\Theta(n)=\Theta(n\log n)$. При последовательных разделениях на 0 и $n-1$:
$$T(n)=T(n-1)+\Theta(n)=\Theta(n^2).$$
Средний индекс массива не гарантирует средний по значению ключ. В среднем $\Theta(n\log n)$ требует модели распределения ключей или выбора опоры.

**Уточнение оценки памяти слайда $O(n)$.** В таком коде родительские входы и уже созданные подмассивы живут во время рекурсии. При сбалансированном разбиении их размеры вдоль ветви дают геометрическую сумму $O(n)$. При крайних разбиениях может оставаться $n+(n-1)+\cdots+1=\Theta(n^2)$ элементов. Поэтому без изменения времени освобождения и владения универсальная граница $O(n)$ неверна.

**Уточнение нижней оценки:** когда все ключи равны, они сразу оказываются в `equal`; рекурсия по двум пустым частям заканчивается и работа линейна. Запись $\Omega(n\log n)$ для **всех** входов именно этой трёхпутевой версии неверна.

В источнике `createVectorBySize(n,...)` сочетается с последующим `pushBack`: нужно различать логический размер и зарезервированную вместимость. Если создано уже $n$ элементов, добавления увеличат размер сверх нужного. Переприсваивание `left = QuickSortStable(left)` может потерять прежнюю оболочку/буфер, поскольку функция не освобождает вход; контракт владения и освобождение старых входов требуют исправления. Опубликованный фрагмент не содержит полной обработки ошибок.

## Разбиение Хоара и quicksort на месте

Другой вариант использует два встречных индекса. Опора выбирается по середине; $i$ движется слева до элемента не меньше опоры, $j$ справа — до элемента не больше. Если $i<j$, элементы меняются местами; иначе $j$ — граница двух частей. Рекурсивные диапазоны `[low,p]` и `[p+1,high]` включительны.

```text
partition(arr, low, high):
    сохранить значение pivot = arr[(low+high)/2]
    i=low-1; j=high+1
    повторять:
        увеличивать i, пока arr[i]<pivot
        уменьшать j, пока arr[j]>pivot
        если i>=j: вернуть j
        обменять arr[i] и arr[j]
```

**Критическое уточнение:** в исходнике `void *pivot = getVectorItem(...)` хранит адрес элемента массива. Если обмен затронет эту ячейку, значение опоры по адресу изменится. Для общего `Vector` необходимо сохранять копию значения опоры и правильно освобождать её. Псевдокод выше явно выражает это условие, не приписывая источнику готовое исправленное тело.

На слайде с `[8,3,7,6,2,5,4,1]` приведены переходы:
`[1,3,7,6,2,5,4,8]` → `[1,3,4,6,2,5,7,8]` → `[1,3,4,5,2,6,7,8]`.
Это показанная последовательность обменов; **она не является трассировкой указанной функции** с начальной опорой `arr[3]=6`: после первого обмена справа уже стоит 4, оно не больше 6 и должно участвовать в следующем обмене. Пример сохраняется с этой оговоркой.

Вариант неустойчив, что показывает пример двух шестёрок выше. Память самого разбиения $O(1)$ элементов, но рекурсивный стек сбалансированной версии $O(\log n)$, худший $O(n)$. Подпись $O(1)$ на слайде не учитывает стек. Время при корректной неизменной опоре имеет обычные условные оценки quicksort: среднее $\Theta(n\log n)$ при соответствующей модели, худшее $\Theta(n^2)$.

## Сортировка Шелла и выбор шагов

Сортировка Шелла выполняет вставки сначала по подпоследовательностям с большим шагом `gap`, затем с меньшими шагами, последний обязательно 1. Элемент может быстро пройти большое расстояние до окончательной вставки.

На слайде дан Python-фрагмент с генератором `AbstractStep`: `step_implements_class(arr)` создаёт генератор, `next_step()` выдаёт очередной шаг. Содержание цикла:

```text
step = next_step()
пока step>0:
    для i от step до n-1:
        j=i
        пока j>=step и arr[j]<arr[j-step]:
            обменять arr[j] и arr[j-step]
            j-=step
    step = next_step()
```

Полные реализации классов генераторов в лекции отсутствуют. Дополнительная память цикла постоянна по $n$; устойчивость обычными дальними обменами не гарантируется.

![[Шелл — разные шаги.png]]

Графики сравнивают Shell, Hibbard, Sedgewick, Knuth при $N=5000,10000,20000,30000,50000$; вертикальная ось — миллисекунды. Это экспериментальная чувствительность к шагам, а не доказательство универсальных степеней.

В исходной таблице под графиками написано:

| Подпись автора | Три указанные оценки |
|---|---|
| Шелл | $O(n)$, $O(n^{3/2})$, $O(n^2)$ |
| Хиббард | $O(n)$, $O(n^{3/2})$, $O(n^2)$ |
| Седжвик | $O(n)$, $O(n^{4/3})$, $O(n^2)$ |
| Кнут | $O(n)$, $O(n\log^2n)$, $O(n^2)$ |

**Оговорка:** конкретные последовательности и соответствие столбцов лучшему, среднему и худшему случаям формально не заданы. Эти подписи сохранены как данные источника, не как доказанные общие теоремы. Для уже отсортированного входа реализация всё равно выполняет проходы по выбранным шагам; утверждение о линейном лучшем времени требует анализа их числа и размеров.

### Фрагмент стохастического анализа

![[Шелл — фрагмент теоретического анализа.png]]

Слайд под заголовком «Доказательство» содержит **фрагмент статьи**, а не полное доказательство. Сохранены формулы этого фрагмента:
$$\mathbb E(|X||Y|)=\frac2\pi\left(\rho\arcsin\rho+\sqrt{1-\rho^2}\right),$$
$$\mathbb E(|X||Y|)=\frac2{\sqrt\pi}(1-\rho^2)^{3/2}
\sum_{k=0}^{\infty}\rho^{2k}\frac{\Gamma(k+1)}{\Gamma(k+\tfrac12)}.$$
Здесь $X,Y$ — совместно нормальные, со средними ноль, единичными дисперсиями и корреляцией $\rho$; контекст уточнён по первоисточнику. Рядовая запись непосредственно применима при $|\rho|<1$.

Для числа сравнений $S_n$ двухпроходного $(h,1)$-Shell Sort на случайных ключах в модели равномерных перестановок в статье приведено:
$$\frac{S_n-n^2/(4h)}{n^{3/2}}\xrightarrow{D}
\mathcal N\!\left(0,\frac1{36h^2}\right)\oplus\frac{W^h}{h^{3/2}},$$
$$\mathbb E S_n=\frac{n^2}{4h}+\frac{\sqrt\pi}{4}\binom h2
\left(\frac nh\right)^{3/2}+o(n^{3/2}).$$
$\oplus$ обозначает свёртку распределений независимых слагаемых; $W^h$ определён в теореме 2 статьи через броуновские мосты, которой на слайде нет. Параметр $h$ здесь фиксирован; это не оценка любой последовательности шагов. Полное доказательство и все определения предельного процесса лекция не содержит. Сверка контекста: [Smythe, Wellner, Stochastic Analysis of Shell Sort](https://faculty.washington.edu/jonw/JAW-papers/jaw-smythe-Algorith01.pdf).

## Подсчёт и поразрядная сортировка

Сортировка подсчётом использует ограниченный диапазон целых ключей: подсчитать частоты, определить положения значений и восстановить порядок. Если ширина диапазона $K$, а элементов $n$, время $\Theta(n+K)$; стандартный устойчивый вариант с выходным массивом требует $O(n+K)$ дополнительной памяти. Это эквивалентно $O(\max(n,K))$, но **$K$ — размер диапазона, а не число встретившихся разных значений**, как подписано в лекции. Если ключи 1 и миллиард, двух разных значений недостаточно для двухъячеечного прямого счётчика без дополнительного отображения.

Поразрядная сортировка LSD обрабатывает ключи от младшего разряда к старшему. На каждом шаге нужен **устойчивый** проход по текущему разряду, иначе прежний порядок младших разрядов разрушится.

Содержание `radixSort` из лекции:

```c
/* Схема автора: n>0, ключи неотрицательные; проверки malloc опущены. */
void radixSort(int arr[], int n) {
    int max = getMax(arr, n), digit = 0;
    int *output = malloc(n * sizeof(int));
    while (max > 0) {
        int count[10] = {0};
        for (int i = 0; i < n; i++)
            count[getDigit(arr[i], digit)]++;
        for (int i = 1; i < 10; i++) count[i] += count[i - 1];
        for (int i = n - 1; i >= 0; i--) {
            int d = getDigit(arr[i], digit);
            output[--count[d]] = arr[i];
        }
        for (int i = 0; i < n; i++) arr[i] = output[i];
        digit++;
        max /= 10;
    }
    free(output);
}
```

`getDigit` и `getMax` в слайде не реализованы: не добавляется предполагаемое авторское тело. `getDigit(x,d)` должен вернуть цифру от 0 до 9; отрицательные значения требуют отдельного правила и исходным кодом не поддерживаются. Пустой вход требует обработки до `getMax`, отказ выделения — до записи в `output`. Полностью нулевой массив уже отсортирован, поэтому отсутствие проходов при `max==0` корректно.

**Почему обратный обход устойчив.** Префиксная сумма `count[d]` — правая граница группы цифры $d$. При проходе справа налево более поздний элемент записывается в более правую свободную позицию; равные цифры сохраняют исходный порядок.

### Полный разбор разрядного примера

На слайде есть конфликт двух исходных подписей: слева `[5,1,15,10]`, справа `[10,1,5,15]`. Частоты у них совпадают; промежуточный итог после единиц `[10,1,5,15]` согласуется с левым входом, поэтому ниже сохранён именно он, а расхождение отмечено.

Единицы массива `[5,1,15,10]` равны `[5,1,5,0]`:

- Частоты по цифрам 0–9: `[1,1,0,0,0,2,0,0,0,0]`.
- Префиксные суммы: `[1,2,2,2,2,4,4,4,4,4]`.
- С конца размещаем 10 в позицию 0, 15 в позицию 3, 1 в позицию 1, 5 в позицию 2. Получаем `[10,1,5,15]`.

Десятки этого результата равны `[1,0,0,1]`:

- Частоты: `[2,2,0,0,0,0,0,0,0,0]`.
- Префиксные суммы: `[2,4,4,4,4,4,4,4,4,4]`.
- С конца: 15 в позицию 3, 5 в позицию 1, 1 в позицию 0, 10 в позицию 2. Итог `[1,5,10,15]`.

Последовательности уменьшения префиксных границ на слайде соответствуют этим четырём размещениям каждого разряда. Устойчивость нужна, например, чтобы 10 осталось перед 15 при общей цифре десятков 1.

Для $R$ разрядов основания $b$:
$$T(n)=\Theta(R(n+b)),\qquad S(n)=O(n+b).$$
При фиксированном $b=10$ это $\Theta(Rn)$ для непустого входа. Линейность по $n$ требует фиксированного числа разрядов; при растущих ключах $R$ также растёт.

![[Сортировки — подсчёт и разряды.png]]

Диаграммы автора при $N=15000,20000$ выделяют Counting и Radix как быстрые в данном опыте. Вывод зависит от диапазона и длины чисел: он не делает эти алгоритмы безусловными победителями для произвольных объектов.

## Сводка условий и оценок

| Алгоритм/вариант | Характерное время | Дополнительная память | Устойчивость |
|---|---|---|---|
| Обменный код слайда «Bubble» | $\Theta(n^2)$ всегда | $O(1)$ элементов | Нет |
| Вставки | Лучшее $\Theta(n)$, худшее $\Theta(n^2)$ | $O(1)$ элементов | Да при строгом сравнении |
| Выбор, гномья | В таблице среднее/худшее $O(n^2)$ | $O(1)$ | Реализация в лекции не дана |
| Слияние с буфером | $\Theta(n\log n)$ | $O(n)$ | Да при выборе слева на равенстве |
| Quicksort на месте | Ожидаемо $\Theta(n\log n)$ при модели, худшее $\Theta(n^2)$ | Стек $O(\log n)$ сбалансированно, $O(n)$ худшее | Обычно нет |
| Трёхпутевой quicksort с массивами | Баланс различных ключей $\Theta(n\log n)$, все равны $\Theta(n)$, худшее $\Theta(n^2)$ | $O(n)$ при балансе, до $O(n^2)$ у показанного владения | Да при сохранении порядка групп |
| Шелл | Зависит от шагов и модели | $O(1)$ элементов у показанного цикла | Обычно нет |
| Heap Sort | В таблице среднее/худшее $O(n\log n)$ | $O(1)$ элементов | Полная реализация не дана |
| Comb Sort | Источник пишет среднее $O(n\log n)$, худшее $O(n^2)$; без модели средняя граница не обоснована | $O(1)$ | Полная реализация не дана |
| Подсчёт | $\Theta(n+K)$ для диапазона $K$ | $O(n+K)$ для устойчивой версии | Да у устойчивого варианта |
| LSD Radix | $\Theta(R(n+b))$ | $O(n+b)$ | Да при устойчивом проходе |
