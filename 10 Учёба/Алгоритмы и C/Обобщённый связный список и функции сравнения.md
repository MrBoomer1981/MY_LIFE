# Обобщённый связный список и функции сравнения

> [!abstract] Суть
> Узлы списка соединены указателями, а данные могут храниться отдельно от узлов. Обобщённый контейнер получает правило равенства от вызывающей стороны через указатель на функцию.

## Узел, голова и интерфейс

```c
#include <stddef.h>

typedef int (*EqualsFunc)(const void *a, const void *b);

typedef struct Node {
    void *data;
    struct Node *next;
} Node;

typedef struct {
    Node *head;
    size_t elem_size;
} GenericList;

GenericList *createList(size_t elem_size);
void appendItem(GenericList *list, void *data);
unsigned int findItem(GenericList *list, void *value, EqualsFunc cmp);
void *popItem(GenericList *list, size_t index);
unsigned int listLength(GenericList *list);
void freeList(GenericList *list);
```

`next` указывает на объект того же структурного типа, у последнего узла он равен `NULL`. Сам список в этой версии хранит голову и размер данных. Простой обход начинается с `head`, обрабатывает `current->data`, затем выполняет `current=current->next` до `NULL`.

Тела создания, добавления, удаления, длины и освобождения в PDF отсутствуют. Поэтому по объявлениям нельзя утверждать, что `appendItem` копирует данные либо только сохраняет переданный указатель. Контракт владения определяет, что освобождает `freeList` и кому принадлежит результат `popItem`.

## Указатель на функцию

Объявление `typedef int (*EqualsFunc)(const void *, const void *)` задаёт тип указателя на функцию: два адреса, целочисленный результат. Это не лямбда и не встроенное замыкание; в данном интерфейсе отдельного окружения нет.

```c
#include <limits.h>

static inline int intEquals(const void *a, const void *b) {
    return *(const int *)a == *(const int *)b;
}

unsigned int findItem(GenericList *list, void *value, EqualsFunc cmp) {
    if (list == NULL || value == NULL || cmp == NULL) return UINT_MAX;
    Node *current = list->head;
    unsigned int index = 0;
    while (current != NULL) {
        if (cmp(current->data, value)) return index;
        current = current->next;
        ++index;
    }
    return UINT_MAX;
}
```

Пример предполагает, что данные каждого узла — корректный объект типа, ожидаемого компаратором. Для `intEquals` это живой `int`. Вызов — `findItem(list, &x, intEquals)` при `int x=5`: имя функции передаётся без вызова.

Данный компаратор возвращает ненулевое при равенстве. У `strcmp` обратное соглашение: равенство — нулевой результат. Поэтому строковому сравнению нужен адаптер, возвращающий `strcmp(...)==0`, с учётом того, содержит узел саму строку или указатель на строку.

В PDF `(unsigned int)-1` используется как «не найдено»; это то же значение, что `UINT_MAX`. Индексы, равные маркеру, недоступны для однозначного результата, и интерфейс предполагает меньшую длину списка. Замена `return index` на `break` внутри успешной ветви была ошибкой исходного слайда: после `break` выполнение дошло бы до возврата «не найдено».

Проверка по оригинальной презентации лекции 6 подтверждает именно такой дефект: `index` увеличивается при обходе, но при совпадении выполняется `break`, а после цикла безусловно возвращается `(unsigned int)-1`. В исправленном фрагменте выше индекс сразу возвращается. Заголовок слайда «По лямбда функциям в C» описывает обычный указатель на именованную функцию; `static inline` не превращает её в лямбда-выражение.

## Сложность и представление

Поиск требует до полного обхода и имеет $O(n)$ при постоянной стоимости сравнения. В списке только с `head` поиск хвоста для добавления тоже $O(n)$, если нет иной сохранённой структуры; `listLength` без поля длины обычно обходит цепочку. Удаление первого узла может быть $O(1)$.

Для очереди с постоянным добавлением в конец нужны сохранённый хвост, а для постоянного получения длины — счётчик. Такие поля отсутствуют в показанном `GenericList`: обещание всех операций за $O(1)$ не следует из его объявления. У двусвязного списка дополнительная связь `prev` позволяет удалить известный хвост без поиска предшественника.
